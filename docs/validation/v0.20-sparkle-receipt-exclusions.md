# External Sparkle Receipt And Setapp Exclusions

Continuation of #607 after reviewed/merged #625 (`6dd4ff03`). This expands
read-only competing-manager evidence, not adoption permission or direct updating.
#606/#607/#608 remain open, and Open App remains the shipping action.

## Contract

- Query the OS-provided `/usr/sbin/pkgutil --volume / --file-info-plist PATH`
  for exactly the app root, `Contents/Info.plist` and validated
  `Contents/MacOS/CFBundleExecutable`. The executable must be a bounded single
  component present as a regular file in the inspected tree; signed metadata
  must agree. No target code, manager executable, shell or installer is launched.
- The internal system-query runner supplies structured argv, fixed working
  directory `/`, stdin `/dev/null`, an empty signal mask, closed unrelated
  descriptors and only fixed PATH/HOME/LANG/LC_ALL environment values. Queries
  have a one-second monotonic deadline and a combined 64 KiB stdout/stderr cap.
  Nonzero status, stderr, spawn/read/wait failures and output/deadline overflow
  reject observation. Cleanup kills/reaps only its own unreaped query child.
  These bounds are not a hard real-time OS scheduling guarantee.
- Require an exact echoed path and the supported plist envelope, at most 128
  claims per path, and bounded nonempty package IDs. Keep sorted/deduplicated IDs
  as diagnostic evidence. Compare the complete bounded replies before/after
  signature validation, including receipt metadata, not only package IDs.
  Finish external queries before final bundle/ancestor revalidation. Missing
  receipts differ from failed queries; failure never grants an empty scan.
- Use the already inspected bundle tree for `Contents/Frameworks/Setapp.framework`,
  `Contents/Resources/setappPublicKey.pem` and
  `Contents/Resources/SetappFramework-Resources.bundle`, with case-insensitive
  matching. Presence is a conservative denial signal, including relocated and
  static-linked apps carrying these resources, not a license or key validation.
  Existing App Store, standard-prefix cask and Setapp-location checks remain.
- Map the two new bits through the private native/Rust ABI to `OtherManager`.
  All 31 nonzero known-bit combinations remain denials and override saved
  adoption. Unknown bits still reject the request. No ABI layout, schema,
  migration, XPC method, app entitlement or shipping capability changes.
- Empty evidence remains `Unknown`/`unresolved`, with `canUpdate: false` and
  `requiresAuthorityResolution: true`. This does not cover nonstandard Homebrew
  prefixes, receipts registering only other payload paths, receipt-less custom
  or managed installations, or Setapp integrations without recognized markers.
  Evidence may change after observation; it is not a filesystem/receipt lock.

The VM's Apple `pkgutil(1)` manual documents the supported file-info plist query
and warns against relying on receipt-storage locations. Product observation uses
that system tool, not private receipt-directory parsing, and requires no Command
Line Tools. Setapp documents the mandatory SDK
[public-key resource](https://docs.setapp.com/docs/add-a-public-key-to-your-app-1),
[static linkage](https://docs.setapp.com/docs/setting-up-the-framework-1),
[resource bundle](https://docs.setapp.com/docs/installing-the-framework-1), and
[vendor API integration](https://docs.setapp.com/docs/prepare-apps-for-setapp).
The API option is why SDK markers cannot establish exhaustive Setapp coverage.

## Verification

All runtime checks run in the disposable arm64 macOS 27.0 (`26A5378j`) VM, under
`/Users/agent/helm-certification/sparkle-receipt-exclusions-20261003`, with isolated
test HOME/temp and an unused explicit development DB path. The production host
only compiles, stages unsigned artifacts and runs static checks. No production
Helm process, database, preferences or accepted GUI profile is changed.
Compilation/staging retain macOS 13.0 deployment compatibility; this is not an
actual Ventura or native Intel runtime certification.

- All 160 native XCTest cases pass. New coverage includes malformed/misdirected
  replies, bounds, environment/argument handling, input EOF, timeout/output flood,
  executable identity, Setapp markers/lookalikes, concurrent target/receipt
  changes and a real read-only OS query. Existing peer, ledger and request tests
  also pass; injected signers/receipt providers keep filesystem fixtures isolated.
- All 17 Rust private bridge tests pass, including every known exclusion-bit
  combination and its ability to fence saved adoption. No core behavior or
  persistence implementation changed; this is not a new full-core/migration run.
- All 17 helper-packaging and five bridge-build contract tests pass in the VM.
  Host Debug/test and Swift Release compilation, unsigned helper staging,
  Rust formatting/Clippy, SwiftLint and docs-sync checks pass. The Release QA
  binary links the development-profile Rust bridge, not a production artifact.
- A real signed Rectangle copy beneath the VM account's Applications directory
  initially returns unresolved. A task-owned package then registers only an
  identical Info.plist at that isolated copy, with no scripts and an empty
  component list disabling bundle relocation. Fresh Release-probe observation
  returns `otherManager`/`installerReceipt` and the exact QA package ID. The
  original installed Rectangle stays unresolved; its metadata/executable hashes
  are unchanged. The copy's code-directory hash is unchanged. Neither app is
  launched or updated, and no consent/session database is opened or created.

This is real native target-signature/receipt evidence from the standalone policy
probe, not new notarized-helper/XPC acceptance or a real vendor update. Existing
#624/#625 signed evidence remains attributed to those sources. Current-source
signed integrated checks remain required before enabling adoption/execution.

Final source artifacts, VM logs, build output and fixture scripts are retained
in the task worktree's ignored `artifacts/` directory. VM final evidence is under
