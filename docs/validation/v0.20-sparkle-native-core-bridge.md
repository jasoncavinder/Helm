# External Sparkle Native-To-Core Preflight

## Scope

Continuation of #607 on merged #622 (`68363740`). This is a read-only integration
slice, not adoption activation or direct-update completion. #606/#607/#608 remain
open; shipping Open App behavior and the app's sandbox/entitlements are unchanged.

`NativeTargetObserver.observeForPolicy(path:)` performs fresh native observation
before invoking a private synchronous C ABI in `helm-external-update-bridge`.
The bridge links `helm-core`, not the application FFI runtime. It copies bounded
UTF-8/byte slices into `TargetObservation` and calls the exact unresolved-target
gate used by `ReviewedAdoption` and adoption resolution. No core policy is
reimplemented in SwiftUI or the helper presentation layer.

- Signature/path success comes only from the local observer. There is no
  JSON/XPC decoder for observations, roots, signature flags or authority.
- Native App Store, Homebrew-cask and Setapp exclusions map to `OtherManager`.
  Missing markers map only to `Unknown`; this is not complete exclusion coverage.
- OS-account application roots remain separate from caller input and `HOME`.
  Rust independently checks permitted root/path shapes. Native observation
  errors propagate without substituting an empty successful scan.
- ABI version, null/oversized slices, UTF-8, boolean and exclusion-bit values
  are checked. Inconsistent receipt evidence is rejected. Unknown return codes
  fail closed in Swift. Pointer validity is an in-process caller contract, not
  a security boundary against arbitrary native code already in the helper.
- `helm-external-policy-probe` outputs a diagnostic and `canUpdate: false`.
  It opens no database, reads no saved permission and exposes no adoption,
  revocation, candidate, download, install or elevation operation. The original
  observation probe's output and bootstrap's exported methods are unchanged.

The core refactor only shares the existing target check; it changes no migration,
consent persistence, boundary requirement or update-state transition. A separate
SQLite integration fixture proves freshly mapped exclusions still reject a saved
grant; vendor-key change and revocation return unresolved. Its synthetic boundary
is test-only and is not signed operational authorization evidence.

## Build Contract

Run `bash scripts/build_external_update_bridge.sh arm64 debug` (or the matching
architecture/release profile), then set `HELM_EXTERNAL_POLICY_LIB_DIR` to the
printed directory for Swift builds. The script locks dependencies, pins macOS 13
for Rust/C, and copies the archive to an immutable SHA-256-addressed directory.
Swift links that exact archive, not a similarly named system library. Changed
Rust contents change the link command and force relinking; missing preparation
fails the build. Swift package metadata resolution itself remains usable.

CI and Swift CodeQL prepare this input before compiling the native package.
Build-contract tests cover architecture/profile arguments, locked builds,
deployment override, same-content reuse, changed-content relinking inputs,
compiler failure, invalid arguments and refusal to overwrite a damaged archive.
