## Contract

The native target observer now excludes the standard `/Applications/MacPorts/`
location and reads `/opt/local/var/macports/registry/registry.db` for registered
file claims. Both the registered `path` and installed `actual_path` are checked
for an exact target or payload path, using case-folded, canonically composed
lexical keys. Inactive retained records remain conservative denials. Similar
prefixes, unrelated paths and general parent directories are not app claims.
These strings are not followed or used as commands. The private bridge maps both
MacPorts denial kinds to bit 5, preserving the existing ABI layout and rejecting
unknown bits. No match still means Unknown/unresolved, never Standalone or adopted.

The standard locations and registry fields follow MacPorts'
[configuration documentation](https://github.com/macports/macports-base/blob/master/doc/macports.conf.5.txt)
and [registry schema](https://github.com/macports/macports-base/blob/master/src/cregistry/sql.c).
This first reader accepts schema 1.215 only. Custom prefixes/configuration,
legacy registries and arbitrary aliases are outside its coverage, not evidence
that an app lacks another manager. This does not change the MacPorts adapter or
Helm's manager enablement policy.

Queries use fixed `/usr/bin/sqlite3`, structured arguments and constant SQL.
Safe mode and `trusted_schema=OFF` deny unsafe schema functions; explicit
`-init /dev/null` prevents user startup SQL. Read-only/query-only settings and
an [immutable URI](https://sqlite.org/uri.html) prevent database creation,
sidecar creation and journal recovery. Because immutable SQLite skips its own
change detection, Helm checks native filesystem identities before and after the
query and repeats the entire observation across target signature validation.
It does not treat an arbitrary live database as an immutable snapshot.

Nonempty WAL/rollback journals reject before querying rather than hide pending
claims. Existing empty journals and bounded shared-memory metadata are allowed,
preserved and included in identity checks. Orphaned sidecars with no registry,
aliased path components, nonregular files, unreadable paths, unknown schemas,
malformed rows, failed system queries or changed evidence reject. Registry reads
are capped at 64 MiB, 100,000 file rows, 4 MiB combined child output and a one-second
child deadline; shared-memory metadata is capped at 1 MiB. Limits fail closed.
Full raw replies participate in equality checks even when normalized claims are
unchanged. External queries finish before final target/filesystem revalidation.

No port command, network request, migration, checkpoint, repair, install or
adoption is performed. Read-only re-observation is not an atomic lease against
other writers or authentication of historical ownership. Complete supported
ownership resolution and native sandbox/peer proof remain required before
operational adoption can be enabled.
