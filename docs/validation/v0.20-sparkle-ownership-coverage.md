# Sparkle Ownership Coverage Gaps

Date: 2026-10-06. Base: merged #638 (`a1dbf0ac`). Product/test commit:
`47798b05`. This is a denial-only native-evidence/adoption guard, not complete
ownership resolution, operational adoption activation or release approval.

## Change

The installed cask observer previously flattened missing/legacy declarations
into an empty claims list. The overall result was still unresolved, but the
staged coordinator could not independently reject those specific gaps if a
future provider incorrectly asserted `ownershipComplete`.

Native evidence now retains `homebrewCoverageGaps`, sorted by scanned token path:

- `missingMetadata`: the token's fixed `.metadata` directory is absent.
- `missingReceipt`: metadata exists but `INSTALL_RECEIPT.json` is absent.
- `missingArtifactDeclarations`: the receipt omits `uninstall_artifacts` or supplies null.
- `emptyArtifactDeclarations`: the declaration array is empty.
- `uninspectedArtifacts`: at least one non-app artifact is not interpreted by this observer.

Mixed app/non-app declarations preserve both matching app claims and the gap.
No non-app artifact is executed or silently treated as fully inspected. This
includes otherwise ordinary receipts with uninstall/pkg/other declarations;
this slice does not certify those artifact semantics. An incomplete unrelated
token is not dismissed based on its name. The finite supported-scope decision
and any safe narrowing of those gaps remain separate work.

The existing descriptor/no-follow, raw-byte/filesystem revalidation, per-file/
aggregate limits, case-equivalent claim matching and failure behavior are
unchanged. Malformed/unreadable input still rejects observation, rather than
returning partial evidence. Missing Caskroom roots and successfully inspected
app-only declarations can produce no gaps, but still do not establish complete
ownership or standalone provenance.

Coordinator preparation rejects known gaps before requesting a storage scope,
even if its injected local complete-ownership assertion is true. The Swift
adoption owner also rejects preparation, and consumes/frees confirmation on
new gap evidence before calling the core grant ABI. Before-admission drift
rejects; after-admission drift reports `outcomeUnknown`, preserving existing
lost-reply semantics and forbidding automatic replay. No Rust migration or ABI
change is needed. Diagnostic field names are machine-readable identifiers,
not new GUI copy or an IPC authority input.
