## Implemented Contract

- An executable Cargo proxy whose version check fails is a failed check, not
  proof that Cargo is absent. Unknown version output also fails closed. Neither
  path publishes an empty installed/outdated snapshot or selects another Cargo.
- Known rustup unavailable/missing Cargo-component signatures receive
  `cargo.toolchain_unavailable`; selected-toolchain context remains in the raw
  error. Guidance offers inspection, not automatic component/default changes.
- DNS and known endpoint-connection failures receive distinct network issue
  keys. They remain process failures; an endpoint incident does not set global
  offline state. Existing offline deferral and bounded read retries are unchanged.
  Cancellation and mutations are never retried by this diagnostic change.
- Cargo compiler failures receive `cargo.build_failed`; the bounded stderr
  excerpt starts at an actionable compiler line rather than dependency chatter.
  Explicit DNS evidence takes precedence over a generic Cargo compilation wrapper.
- These classifications do not recommend rerunning a mutation as a diagnostic
  probe. Raw command/output context is retained for inspection.
- Terminal error/log markers map to guidance in all seven GUI locales. Matching
  requires the process-failure code and a leading recognized marker, not arbitrary
  text embedded in another error.
- The persistence receipt includes failure diagnostic records before synchronous
  CLI callers may exit. Other nonessential notes remain outside this boundary.
  There is no schema or migration change.

## VM Evidence

All product execution and test suites ran in the disposable macOS VM, with
isolated HOME, TMPDIR and HELM_DB_PATH. Host work was editing, compilation and
static checks only. The installed production app, database and Rust tools were
not modified, relaunched, upgraded or repaired.

- Regression classification was red before the implementation and green after.
- Cargo process/runtime/store regression covers the exact recorded unavailable
  component signature, genuinely missing component, ordinary command failure,
  successful-but-empty version output, and healthy recovery. Installed packages
  and outdated snapshots survive all failures; the fake rejects repair commands.
- Unknown/connected/disconnected network states cover persistent and transient
  DNS failures. Read retries remain bounded; cancellation and install failures
  do not retry, and one endpoint cannot mark the runtime globally offline.
- A deliberately blocked diagnostic write reproduces the CLI receipt race before
  correction and passes afterward. Existing ordered response persistence and
  cancellation regressions remain passing.
- Core suite: all 50 compiled test executables pass, including 807 unit tests,
  29 adapter-runtime integration tests and two Cargo end-to-end tests. Five
  opt-in real-environment tests remain ignored by design, not certified here.
- Swift suite: 372 tests pass in the VM, including trusted-marker matching,
  seven-locale guidance and canonical/bundle locale parity.
- Real CLI: copied an existing VM toolchain into a new disposable scope, removed
  only that copy's Cargo component with rustup, observed Helm's actionable failed
  detection, restored the component explicitly, and verified healthy detection
  and an identical installed-component list. No user's default was changed.
- Real CLI: scoped RUSTUP_DIST_SERVER to `https://helm-certification.invalid`,
  observed native rustup DNS failure through Helm, then restored the official
  endpoint and completed refresh. No system network settings were changed.
  A separate CLI process reads the persisted `network.dns_resolution_failed`
  record after the failing command exits. Local inventory remains available.
- Host compilation targets arm64/macOS 13. Strict Clippy, rustfmt, SwiftLint,
  locale checks and immutable 21-entry migration manifest pass. Migration,
  process recovery, CLI recovery and FFI initialization boundaries run in the VM,
  equivalent to the runtime portions of the SQLite compatibility gate.

Raw VM test/output artifacts are retained under the task worktree's ignored
`artifacts/` directory and VM `helm-certification/rust-diagnostics-20260927` scope.
The initial DNS setup probe was blocked by missing shell configuration in the
new test HOME; normal setup was added only there before the recorded DNS checks.
That setup-policy rejection is not counted as a DNS test pass.
