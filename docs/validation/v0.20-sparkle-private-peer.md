real private-service transport's signed/notarized peer matrix. This follows
merged #635 (`93b62fc95c7bba29e0c88141e6ea21434f400df6`) and its separate

## Controls And Results

The five wrappers contain `Contents/MacOS/BootstrapProbe` and a service at
`Contents/XPCServices/com.jasoncavinder.Helm.SparkleExternalUpdater.xpc`.
All use the project's Developer ID team, hardened runtime and notarization.
The helper carries its own pinned Sparkle 2.9.5 framework. Signing was inside-out,
not deep signing; Sparkle's existing nested entitlements were preserved.

| Wrapper | Caller metadata / entitlements | Nested service |
| --- | --- | --- |
| Valid | Exact Helm ID, `developer_id`, only app-sandbox true | Exact helper ID, no entitlements |
| WrongCaller | `.WrongCaller` ID suffix, otherwise valid | Same real helper |
| WrongChannel | Exact Helm ID, `mas`, only app-sandbox true | Same real helper |
| UnsandboxedCaller | Exact Helm ID, `developer_id`, no entitlements | Same real helper |
| ImpostorHelper | Exact Helm ID, `developer_id`, only app-sandbox true | Fixed lookup bundle ID, signed as `.WrongHelper`, fixture executable |

No caller has a Mach-lookup exception. The runner checks sealed caller metadata,
entitlements, signatures and Gatekeeper before launching. Each real helper also
passes standalone native self-preflight, ruling out broken packaging as the
explanation for a caller-negative result; this self-preflight is not itself
launch-boundary evidence.

The impostor must actually start and receive hello; a startup failure cannot pass
that control. It echoes the challenge with a syntactically valid fake nonce, so
the check exercises the client's native response gate, not a malformed reply.
Fresh marker directories and exact transport-rejection output are required;
timeouts, launcher failure or other rejection reasons do not count as success.
Rectangle's Info.plist and executable hashes remained unchanged, and no isolated
development database was created. No app update, adoption grant or ledger
mutation was attempted.

## Reproduction And Retained Evidence

With separately approved pre-signed/notarized/stapled wrappers, run only in the
disposable VM, with a new output directory and the unchanged Rectangle fixture:

```sh
python3 scripts/tests/external_xpc_signed_vm.py --confirm-disposable-vm \
  --payload /existing/qa/Payload --output /existing/qa/new-run \
  --target /Applications/Rectangle.app
```

The runner copies wrappers without installing them and records signatures,
Gatekeeper, entitlements, helper self-preflight, per-case stdout/stderr, caller
and service hashes, and `summary.json`. Exact-identifier callers may use the
disposable account's app sandbox container; the VM-only restriction is essential.
The flag is an operator acknowledgment, not VM detection or a security boundary.

Evidence is retained under VM
`/Users/agent/helm-certification/sparkle-private-peer-20261005/` and the matching
task worktree's ignored `artifacts/` directory. Earlier `signed-1` and `signed-2`
runs passed; `signed-3` uses the final runner above. Signing/staging scripts,
notarization result, stapling logs, signed payload, native test logs and signed
matrix outputs are preserved, not committed as binaries.

Release and Debug Swift/test compilation passed with a freshly built optimized
Rust archive. The VM passed 250 native Swift tests, 21 packaging contracts and
five bridge-build contracts. Strict SwiftLint passed for both changed Swift
files. No Rust implementation or migration changed; this does not claim a new
full Rust, migration, app UI, Ventura-runtime or Intel gate.

The first impostor compile lacked `-parse-as-library`; the corrected compile
passed. The first sandboxed stapling attempt failed with local error 66 and
`kLSDataUnavailableErr`; the approved outside-sandbox retry stapled and validated
all five wrappers. Neither failed tooling attempt is counted as peer evidence.
