# Dashboard Add Manager Validation

Tracks [issue #463](https://github.com/jasoncavinder/Helm/issues/463). This is a v0.20 development workflow, not a change to published v0.19.1.

## Contract

- Manager Health always ends with a distinct Add manager button, including when no managers are detected.
- The chooser uses the service's planner-filtered `installMethodOptions`, not `ManagerInfo`'s broader distribution-method registry or a second list of installable manager IDs.
- Only implemented, undetected managers with recognized core method metadata appear. Detected-but-disabled managers remain in Environment and are not installation candidates.
- Policy-blocked methods and missing/disabled/ineligible/busy dependencies remain visible with an explanation. Unknown policy tags and missing eligibility fail closed. A manager can proceed if at least one supported method is ready.
- Service disconnection, offline state, loading, and research previews have explicit presentation. No preview can submit live operations.
- Review Installation closes the chooser, clears any Environment domain filter, scrolls the selected manager into view, reveals its inspector, and opens its existing installation sheet. The one-time scroll waits for the destination rows and cannot consume a newer request. It does not install, enable a manager, or apply preferences.
- `cargo-binstall` supports both Cargo and Homebrew installation. The explicit Cargo method routes through the existing Cargo adapter with `cargo install cargo-binstall --locked`, following the upstream source-install recipe. It requires a ready Cargo dependency, not a complete crates.io catalog or cached search result. Existing default/persisted Homebrew routing is preserved; the unimplemented script method remains excluded.
- The native toolbar keeps Refresh/Review Plan and the Plan manager filter leading, with search and the details toggle in separate trailing items, in that order. All supported releases use the existing native `NSSearchField` bridge, Command-F focus router, and hidden principal alignment anchor. Tahoe gives search its own native glass surface instead of hiding its background or sharing one with Details; older releases retain their existing appearance. Apple's [default search item placement contract](https://developer.apple.com/documentation/swiftui/toolbardefaultitemkind/search) does not support the macOS top-toolbar repositioning assumed by the first attempt. Neither window geometry nor sidebar behavior is overridden.
- The selected method is checked again against current metadata and dependencies before submission and after each asynchronous preference callback. A different available method cannot silently replace an unavailable selected method. Missing methods never trigger a direct-install fallback.
- After explicit Install confirmation, the existing core/service task path remains responsible for execution, authorization, progress, cancellation, verification, failure reporting, and recovery. The UI does not introduce shell execution, credential handling, or a second installer.

## Owner QA

Use a signed Debug build in `Helm-Development`, not the stable database. Do not click Install on the owner's Mac merely to validate navigation.

1. Open Dashboard. Add manager is the final, visibly distinct Manager Health card. It is reachable with both Tab and Shift-Tab and announced as a button by VoiceOver.
2. Open the chooser. Installed managers, including disabled installed managers, are absent. Unavailable methods name their policy block or prerequisite. Cancel and Escape close the chooser without creating tasks.
3. Select an available manager and choose Review Installation. Environment opens with that manager selected and scrolled into view, the inspector visible, and the existing installation review sheet open. Confirm the method/source/advanced options, then Cancel. No installation task should appear. Repeat with cargo-binstall: both Cargo and Homebrew methods should be listed; a missing/disabled/busy dependency disables only its corresponding method.
4. Repeat after visiting a filtered Environment route and hiding its inspector. The handoff clears the route filter and reveals the correct inspector. Repeat opening/cancelling to catch presentation-transition regressions.
5. While the chooser or installation review is open, go offline. Review/Install must become unavailable. Reconnect and verify that current readiness is re-evaluated; no task should be submitted automatically.
6. Check Light/Dark and live language changes, especially German, Hungarian, and Japanese. Check selection and both footer buttons with Full Keyboard Access and VoiceOver; long method explanations must wrap without hiding the footer.
