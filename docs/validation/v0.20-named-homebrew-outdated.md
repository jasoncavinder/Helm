# Named Homebrew Outdated Results

This is #605's original correction/evidence, now reviewed and merged. The later
[delegated refresh policy](v0.20-homebrew-refresh-policy.md) records #603's
cold-cache/implicit-auto-update follow-up and narrowly extends the stderr contract
below for verified successful API-download reports. The original evidence is not
relabelled as validation of that follow-up.

## Scope And Cause

Follow-up to [#603](https://github.com/jasoncavinder/Helm/issues/603), based on
merged #604 (`630e7617`). Implementation/test source: `11eb70f1`.

Homebrew's [outdated implementation](https://github.com/Homebrew/brew/blob/4e2303faf7/Library/Homebrew/cmd/outdated.rb)
sets its failure status when a named query finds outdated software. An unnamed
all-formula/all-cask query does not use that signal. The supplied macOS 27 arm64
VM reproduced this with native Homebrew queries:

| Query | Native exit | Observed result |
|---|---|---|
| `outdated --json=v2 --formula podman` | 1 | 6.1.2 -> 6.1.3 |
| `outdated --json=v2 --formula colima` | 0 | No update |
| `outdated --json=v2 --cask docker-desktop` | 1 | 4.92.0,240144 -> 4.93.0,240920 |

The first read-only query auto-updated Homebrew itself from `319df2375c` to
`4e2303faf7`; subsequent evidence commands disabled auto-update. No formula,
cask or application was installed, upgraded or removed for these checks.

Podman, Colima and Docker Desktop previously used the strict zero-only stdout
collector and could reject a legitimate update. The unnamed Homebrew formula
and cask adapters remain strict and unchanged.

The Docker audit also reproduced a separate false-current result: its cask
installation check expected a string `name` and formula-style `installed`
array. Current cask info has a `token`, display-name array and installed-version
string. The old CLI returned success with zero Docker updates despite the native
outdated result above. The correction accepts the current receipt shape, retains
the validated legacy fixture shape, rejects absent/blank installation evidence
and never substitutes a display name for a conflicting token.

## Contract

- Only the exact three named `brew outdated --json=v2` requests can accept exit 1.
- Acceptance requires exactly one matching entry in the correct collection,
  an empty opposite collection, a nonempty candidate and nonempty string installed
  versions. Empty, malformed, unrelated, mixed and duplicate entries fail.
- Nonempty stderr accompanying exit 1 remains a failure, deliberately retaining
  unexpected diagnostics rather than assuming they are harmless. This is a
  conservative boundary, not general classification of Homebrew warnings.
- Other exit codes, signals, spawn/wait errors, cancellation and timeouts retain
  their original failure behavior and process context. `brew info` stays strict.
- Exit-zero parsing behavior is unchanged. No new mutation capability, ownership
  rule, pin policy, automatic installation or bulk execution is added.

## Verification

All runtime execution was inside the disposable VM in a new private scope:
`/Users/agent/helm-certification/brew-outdated-20261001/`.
The owner's host production app and previously accepted VM QA profiles were not
changed. Runtime tests used isolated HOME/TMPDIR/database paths. Live CLI checks
used separate `before.db` and `after.db` profiles with explicit test-scope CLI
license/default acknowledgment, not the GUI service database.

- 865 core unit tests passed, including existing process-collector diagnostics
  and expected-status behavior plus current/invalid Docker cask receipt cases.
- Five new process-source regression tests passed. Their matrices cover all
  three sources and both adapter Refresh/ListOutdated routes, exit 0/1 success,
  no-update success, empty/malformed/unrelated data, invalid versions/collections,
  other nonzero codes, stderr, signals, spawn/wait errors and strict `brew info`.
- A negative control using real-shaped Docker info failed with zero candidates
  before the receipt correction; the same test now passes. Native Docker app
  discovery is stubbed only in this deterministic test; real CLI checks use
  actual installed applications and native executables.
- Real CLI refresh and cached update readback passed for all three managers,
  with the versions in the table above. All nine persisted detection/inventory/
  outdated tasks were completed, with no failed tasks or mutation tasks.
- Host compilation (`cargo test --no-run`, CLI build), formatting, Clippy for
  helm-core/helm-cli all targets with warnings denied, docs-sync and whitespace
  checks passed. No host runtime test was used.

The first automated attempt had a test stub missing Colima's `version` command;
the stub was corrected. The first full core run used the workspace rather than
crate working directory, producing four missing Bundler fixture failures (861
passes). Rerunning from the correct crate directory passed all 865 tests with no
product changes. These attempts are preserved, not counted as passes.
