# Cargo Source-Build Timeout Correction

Status updated 2026-10-01: automated regression checks and bounded signed GUI
warm recovery pass. This is not a cold-build runtime certification.

## Observed Failure

During item 11 of the [integrated owner QA](v0.20-integrated-owner-qa.md), real
Cargo installation of cargo-binstall 1.24.0 failed as task 24 on signed source
`da59f589`. Helm reported a 300-second base hard timeout, 300 seconds of bounded
activity extension, then no user response within the 30-second decision window.
The old five-minute mutation default was inappropriate for this source build.

The saved diagnostic shows registry/download activity and an upstream locked
dependency warning, not a compiler error. That warning is not grounds for
removing `--locked`. Full process output was unavailable through the separate
CLI; the record does not claim a complete compiler transcript. Native readback
confirmed no remaining Cargo/rustc process, no installed binary or receipt,
unchanged unrelated Homebrew inventory and preserved earlier accepted profiles.

## Bounded Policy Change

- Cargo install and upgrade/reinstall source-build requests default to a
  30-minute hard timeout instead of five minutes.
- Existing bounded activity extensions and the timeout-decision flow remain
  unchanged; 30 minutes is the base budget, not an unconditional total ceiling.
- Explicit manager hard/idle timeout preferences retain precedence, including
  shorter hard timeouts. There is still no default mutation idle timeout.
- Version detection (10 seconds), installed listing (60 seconds), registry
  search (30 seconds), crate metadata (120 seconds) and uninstall (five minutes)
  keep their existing budgets.
- Structured arguments, locked dependencies, exact reviewed versions, registry
  provenance, cancellation, receipt verification and install-root isolation are
  unchanged. No retries are automatic and no user preference is migrated.

This is shared core policy for CLI and GUI, not a QA-only override or a global
extension for unrelated managers.

## Signed GUI Recovery

The corrected Developer ID-signed source `41c01768` retained the isolated manager
database, failed history and default timeout preferences. Its first retry hit
VM disk exhaustion, not the previous five-minute timeout. After owner-approved
removal of six obsolete build directories, measured free space increased by
28.8 GiB. Current binaries, the warm Cargo cache, databases and earlier accepted
profiles were preserved. Startup reconciliation cancelled stale task 37 without
changing its creation time; no compiler remained and no retry was automatic.

The owner explicitly retried and reported successful GUI completion. Readback
confirmed cargo-binstall **1.24.0** through its native `-V`, Cargo's exact-version
receipt and installed listing, Helm's installed-package inventory, and manager
detection at the same isolated executable. Neither Cargo nor cargo-binstall has
a hard/idle timeout override. No install task or compiler remains active. The
earlier accepted profiles and unrelated Homebrew inventory were unchanged.

Completed task/log entries were no longer retained at readback. Acceptance
therefore combines owner-observed completion with native/database postconditions,
not an independently captured successful task ID or duration. Retained compilation
artifacts make this a warm recovery pass, not a cold-build benchmark.

The temporary Homebrew cargo-binstall fixture was then restored to 1.24.0 through
the same bundled Helm CLI in a separate restoration database. Other formula
versions and the isolated Cargo installation were preserved. Evidence includes
`cleanup-result-20261001.json`, `disk-recovery-result-20261001.json`,
`after-owner-manager-success.json`, its database snapshot and the separate
`homebrew-restoration/` command records under the private VM scope
`/Users/agent/helm-certification/cargo-timeout-41c01768` and local task artifacts.
This closes item 11's bounded recovery check, not Cargo/uv GUI parity or the
remaining release gates. No host production installation was changed.
