# v0.20 Real First-Run Wayfinder Evidence

## Scope

This presentation-only continuation of the real entry and reviewed repair work
replaces the compact Debug evidence list, not the startup/controller contracts.
It remains behind `HELM_FIRST_RUN_PRODUCTION_QA=1`. Shipping startup, legal
acceptance, acknowledgment, repair consent and activation are unchanged. It is
not participant evidence or approval to activate the new route in Release.

The familiar Wayfinder composition now uses an honest local-evidence vocabulary:

- The circular ornament reports a count of sources with candidate files. It is
  not a progress percentage, readiness score or count of working installations.
- Saved enabled/disabled counts describe existing preferences. Unconfigured
  sources are not silently assigned either preference or declared ready.
- Candidate paths, saved executable selections, cached detections, incomplete
  scans and out-of-scope scans remain distinguishable. Full paths are selectable
  and wrap rather than being truncated into an ambiguous installation identity.
- Sources with relevant evidence are shown first; remaining sources are under
  a disclosure, never discarded or relabeled as definitely not installed.
- Only the software-source list scrolls. Review Repair and Use Helm Now remain
  outside it, with the existing consent/activation disclosure. Scan Again stays
  in the header. The existing fixed `960x600` first-run host is unchanged.
- Native disclosure controls, stable accessibility identifiers, explicit
  title-before-count labels and observed localization are retained. No animated
  progress or synthetic health/repair result is introduced.

## Required Signed Acceptance

Do not infer visual or accessibility acceptance from the automated pass. A
same-source signed QA build still needs these bounded owner checks in the VM:

1. Open the real entry with existing preferences and with a fresh isolated
   store. Confirm truthful counts, partial/not-scanned distinctions, saved paths
   and zero manager/network work before explicit continuation.
2. Expand many sources and long paths; only the right list should scroll. Scan,
   optional Repair and Use Helm Now must remain reachable at the fixed size in
   Light/Dark and representative long/+40% expanded locales.
3. Traverse native disclosures/actions in both keyboard directions and with
   VoiceOver. Check the heading, count order, path labels and focus geometry.
4. Change language while the evidence is open. Confirm live labels, no raw keys
   and no loss of the selected consent/repair state; then exercise the separately
   documented repair and relaunch acknowledgment checks.

Actual Ventura/Tahoe rendering and participant thresholds remain separate gates.
