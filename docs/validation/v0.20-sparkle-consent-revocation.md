# Authenticated Sparkle Consent Revocation

Date: 2026-10-03. Base: `33e82095` (merged #627). Scope: **denial-only**,
helper-owned review/confirmation. Part of #607; #606/#608 remain open.

## Contract

`reviewRevocation` accepts only schema version 1, UUID request ID and a normal
allowed-root `.app` path. No client database path, epoch, revision, authority,
target trust assertion or approval flag is accepted. It runs only after the
existing signed-peer/account handshake. Removal deliberately does not require
the app to exist, retain its signature or remain eligible for adoption.

The helper obtains its OS-account root, re-observes its identity and uses the
existing-only private storage lease. A read-only transaction validates the
current schema/manifest/integrity and captures the path revision and database
epoch. A nonserializable native review holds those values. Only a random 32-byte
connection-local handle is returned; it is not update authority. There is one
pending review per connection; a new review replaces it, and disconnect clears it.

`confirmRevocation` consumes the handle, reacquires the same private lease and
rechecks helper/root identity. Immediately before core mutation, it synchronously
requests one-time admission on the transport's serial queue. The connection,
sequence, request deadline and session lifetime must still be live. Native/core
review age is also checked, including clock regression and the 120-second limit.

Core opens existing READ_WRITE/NOFOLLOW storage without CREATE or migrations.
Inside `BEGIN IMMEDIATE`, it revalidates the schema and atomically compares the
reviewed epoch/path revision. If unchanged, it appends a revocation tombstone and
commits with FULL/fullfsync. A stale review cannot revoke a newer grant, even
across processes. New explicit reviews may revoke an already-revoked/no-grant
path to fence pending adoption reviews. Replaying the old handle cannot.
See SQLite's [transaction contract](https://www.sqlite.org/lang_transaction.html)
and [synchronous semantics](https://www.sqlite.org/pragma.html#pragma_synchronous).
This requests durability, not a hardware/power-loss guarantee.

| Code | Result | Meaning |
| --- | --- | --- |
| 39 | reviewed + handle | Read-only review prepared on this connection. |
| 40 | `revoked` | Reviewed revision was revoked and native postchecks passed. |
| 41 | `reviewChanged` | Epoch/revision/path changed or native review expired. |
| 42 | `outcomeUnknown` | Storage or post-admission validation failed; no safe retry inference. |

These methods and both existing diagnostics share eight total requests, strict
sequence/replay checking, single-flight execution, 8 KiB requests, 15-second
request deadlines and a 120-second connection lifetime. Reply codes/payloads
must match the pending method. The client does not replay any operation.

Cancellation/loss/expiry **before admission** prevents the write. If admission
wins that race, the write can commit even after cancellation, without a delivered
result. No late result is published and no automatic retry occurs. A transport
failure after sending confirmation therefore also means uncertainty, not proof
of no mutation. A subsequent human decision requires fresh history/review.
Revocation never frees an active install reservation, aborts a handed-off
installer, grants authority or bypasses manager ownership. Safe mode still allows
denial-only removal. Incomplete/corrupt/unsafe/busy storage fails closed, with no
recreation or repair. Existing migration definitions are unchanged.

## Scope Limits

No main-app embedding, shipping GUI/CLI control, adoption grant, accepted Sparkle
candidate, downloader, installer, relaunch or release publication is enabled.
Open App remains the shipping behavior. Remaining gates include complete supported
ownership checks, authenticated adoption grants, operational durable sessions,
shared review UX and real install/verification/recovery acceptance. VM evidence
does not certify native Intel hardware or Ventura runtime behavior. The private
ledger is not tamper-proof against the same account/root or restored old backups.
