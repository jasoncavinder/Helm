## Production Fixture Contract

Debug builds accept `HELM_WAYFINDER_POPOVER_FIXTURE` with one of these values:

| Fixture | Condition | Affected route | Key evidence |
|---|---|---|---|
| `healthy` | Healthy | All current | 17 detected sources; no primary action |
| `updates-ready` | Updates Ready | Apps and Packages | Four reviewed-plan updates |
| `running` | Active work | Apps | Determinate 5-of-12 progress |
| `needs-review` | Actionable finding | Tools / `mise` | Multiple-install decision context |
| `error` | Failed work | Apps | Recovery action and error route tone |
| `offline` | Offline/cached | All cached | Saved-state action; refresh unavailable |

The fixture is projected through `WayfinderProjectionProjector` and `WayfinderPopoverPresentationProjector`, then rendered by the production `WayfinderPopoverView`. It does not use the separate design-lab renderer.

While a fixture is active in a Debug build:

- the popover bypasses onboarding so the requested state is immediately reviewable;
- launch, manual, and reconnect-triggered Helm refresh requests are ignored;
- scheduled, information-only, and manual Helm self-update checks are ignored;
- refresh and Helm-update controls retain their production appearance, but requests safely no-op;
- Release builds ignore the environment key.

The fixture replaces popover presentation only. Dashboard destinations continue to read the development profile, and synthetic task IDs do not create matching Plan or Activity records. Route controls can validate destination/domain wiring, but a full moderated session must not use them as evidence for destination content or workflow completion until each destination consumes the whole-workflow dataset through its production presentation path.

## Safe Launch

Use a Debug app built from this branch. Debug service builds use Helm's `Helm-Development` database namespace; do not launch this fixture against the stable application bundle or stable user database.

In Xcode, add the fixture key and one state value to the Helm scheme's Run environment. From a terminal, launch the executable directly so it inherits the environment:

```bash
HELM_WAYFINDER_POPOVER_FIXTURE=needs-review /path/to/Helm.app/Contents/MacOS/Helm
```

To inspect Task 1 from the status-item popover, Task 2 through Plan, Task 3 through Library/global search, Task 4 through Activity, Task 5 through Environment, Task 6 from General Settings back to Activity, or Task 7 through first run in a signed sandboxed build, copy the canonical corpus into Helm's readable container before selecting it. The source remains the versioned authority; the runtime copy is disposable. For Task 1, begin with Helm backgrounded and open the popover; for Task 3, search for `ripgrep`; for Task 6, use Command-Comma to change Launch Helm at login, close Settings, and return to failed Activity `7001` for Copy Diagnostics. The app does not start its service or permit package/update work in this mode:

```bash
fixture_source="$PWD/docs/validation/fixtures/v0.20-whole-workflow-v1.json"
fixture_runtime="$HOME/Library/Containers/com.jasoncavinder.Helm/Data/tmp/v0.20-whole-workflow-v1.json"
mkdir -p "$(dirname "$fixture_runtime")"
cp "$fixture_source" "$fixture_runtime"
HELM_WAYFINDER_RESEARCH_DATASET="$fixture_runtime" \
  /path/to/Helm.app/Contents/MacOS/Helm
```


A signed sandboxed app cannot read an arbitrary worktree path merely because the path is supplied through the environment. If the copy or selected path is unavailable, the research selector fails closed rather than falling back to live data.

Quit other Helm development processes before changing fixture states. Use the same build and dataset version for every compared capture.

The benchmark opens the production panel, records acknowledgement after `makeKeyAndOrderFront` plus app activation, forces the hosted content's layout/display, records first useful render, emits one machine-readable result line, and terminates.
