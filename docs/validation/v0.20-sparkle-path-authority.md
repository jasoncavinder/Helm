# External Sparkle Helper Filesystem Boundary

Date: 2026-10-02. Base: merged #619, `23133525`.

## Scope

This slice closes a helper self-observation gap before #607's native manager
authority mapping. A valid code signature alone does not prove that the helper's
installation path or files cannot be replaced by other accounts. The existing
target observer's filesystem code is now shared with helper observation.

- Inspect every parent through `/`, not only the immediate installation root.
- Accept only root/current-account ownership. Reject group/world mutation mode
  bits and conservatively reject any ACL mutation allow grant. The existing
  root-owned `/Applications` admin-group mode exception does not extend to an
  arbitrary directory with that name or to ACL grants.
- Inspect the complete bundle tree with the existing 100,000-entry bound;
  reject special/set-ID files, escaping, dangling and cyclic links. Ordinary
  contained framework symlink layouts remain supported.
- Open permission and bounded metadata descriptors with `O_NOFOLLOW_ANY`, so
  an intermediate alias cannot silently redirect the open to another object.
- Compare full descendant/ancestor identity snapshots around signature
  validation and across repeated self-observations. Identity includes ownership,
  group, mode, size, inode/device and nanosecond change/modify times, excluding
  access times. Read-only ACL changes also invalidate the snapshot via ctime.
- Helper tree mutation grants are rejected, whereas the target observer retains
  its existing non-authorizing `writableByOthers` fact and unresolved provenance.

The helper still obtains its path from `SecCodeCopySelf`/`SecCodeCopyPath`, not a
client. Native requirements, notarization, hardened runtime, channel checks and
app entitlements are unchanged. No shell, network fetch, installer, updater
instance, database change or operational XPC method is added.

## Limits And Next Gate

No standalone manager authority is inferred from a safe directory or absence of
a receipt. Homebrew/Setapp/App Store/other authority resolution, Sparkle-accepted
candidate observation, durable operation binding, shipping launch/installation
root policy and inherited-sandbox proof remain open in #607. A snapshot is not
an atomic path reservation and cannot prevent changes after observation. Root
and the current account remain in this filesystem trust model; the system
Applications admin mode exception is intentional, not a security attestation
against administrators. Native signing validation remains independently required.

#608's installation, authorization, relaunch, cancellation, verification and
recovery integration follows. #606/#607/#608 stay open and direct updates remain
disabled. No new user-facing text, shipping UI, database or locale keys changed.
No owner GUI recheck is required for this read-only helper slice. Ventura/native
Intel runtime and final integrated-candidate QA remain separate release gates.

API reference: Apple's [Darwin open flags](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/fcntl.h)
define `O_NOFOLLOW_ANY` for refusing symlinks in the complete path. The local
macOS SDK declaration was checked before use; target minimum remains macOS 13.
