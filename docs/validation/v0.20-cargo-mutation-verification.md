# v0.20 Cargo Mutation Verification

Date: 2026-09-27. Partial implementation follow-up for
[#564](https://github.com/jasoncavinder/Helm/issues/564), not closure of the
[dependency-resolution issue](v0.20-cargo-dependency-reproduction.md).

## Delivered Boundary

- Explicit adapter install/upgrade versions must be complete SemVer versions,
  including optional prerelease/build metadata, not ranges or partial versions.
  Unversioned install remains supported and reports the observed version.
- Upgrade honors an explicit adapter version. Otherwise it resolves candidates
  once at task start and passes each exact version to `cargo install --force
  <name> --version <version>`. Postverification does not query the registry again.
- All batch targets are validated before the first mutation. Each package's
  local version is rechecked immediately before execution and after completion.
  Already-current targets are observed without forcing another compilation.
- Install/upgrade success requires an unambiguous native `cargo install --list`
  entry with the expected version, when one was specified. Missing, wrong,
  malformed, duplicate, or source-annotated target entries cannot produce a
  guessed success version. Uninstall checks that the entry is absent.
- Inventory/read failures, timeout, cancellation and native command failure
  propagate. There is no automatic retry, alternative installer, toolchain
  repair, global configuration change, or new general `--locked` default.

The shared display parser is not used as mutation evidence: it previously
accepted source annotations as part of a version and selected the first match.
The stricter mutation parser rejects ambiguous/unsupported target evidence.
Ordinary inventory/search presentation and cargo-binstall remain unchanged.
Incomplete Cargo outdated entries now fail parsing rather than disappearing.

## Verification

Host preparation compiled binaries and ran formatting/Clippy only. All product
and test execution used the disposable macOS 27 arm64 VM with isolated HOME,
TMPDIR, database and installation roots. The owner's production Helm and Rust
installation were not changed.

- Two regressions fail on the old implementation: install can report requested
  0.25.0 while 0.24.0 is installed; an explicit upgrade can succeed with an empty
  outdated response while 0.24.0 remains. Both pass with the correction.
- Full compiled core/FFI test suite passes in the VM, including 809 core unit
  tests, 106 FFI tests, ten new mutation-contract tests, two Cargo orchestration
  tests, migration/recovery tests and the #569 diagnostic/persistence regressions.
  Five existing opt-in environment tests remain ignored, not certified by this run.
- The new contracts cover explicit/discovered versions, no remote postverification,
  malformed/ambiguous/source-annotated inventory, partial/range rejection,
  pre-mutation drift, batch preflight, no-op upgrades, failed verification, injected
  cancellation/timeout propagation, and no invented candidate persisted as installed.
- Real Helm CLI installs crates.io `sd 0.7.6`, upgrades it to `1.0.0`, verifies its
  executable output/native inventory/receipt, observes a redundant upgrade without
  reinstalling, and removes it with native inventory and executable absence verified.
  CLI JSON reports the observed before/after versions. Cargo and rustc are 1.98.1.
- Workspace Clippy with warnings denied, rustfmt, diff whitespace and docs-sync
  checks pass. No UI code or localized presentation was changed.

## Still Required Before #564 Closes

This is **installed-version verification**, not complete artifact/source proof.
Native inventory is not an executable hash or receipt-feature comparison.

1. Preserve the [candidate plan-binding follow-up](v0.20-cargo-plan-binding.md):
   reviewed GUI plans and CLI workflows now carry exact candidates, and direct
   FFI requests retain explicit versions. CLI `packages upgrade` remains
   unversioned and freezes at task start; a separate `updates preview` invocation
   is not a persisted approval for a later `updates run`. No CLI syntax changed.
2. Bind selected Cargo executable, installation scope, registry source and native
   receipt across execution. Preserve supported features/bins/profile/target or
   fail closed. Source-annotated list entries are rejected now, but plain registry
   entries alone cannot distinguish private registries or custom build choices.
3. Establish the published lock graph and explicit missing/stale-lock behavior
   before changing dependency policy. The slint-viewer native locked experiment
   is not a successful Helm upgrade under a new policy.
4. Complete source/receipt reconciliation, interruption/failure preservation and
   build-timeout coverage through the real CLI, then signed GUI/Plan parity QA.
   A batch is not atomic: earlier successful packages are not rolled back when a
   later package fails, and the aggregate result does not claim one batch version.

No release gate, platform certification or maintainer disposition is waived.
