# v0.20 First-Run Local Observation

Status: implemented read-only core/FFI/XPC building block for #561. Production
first-run entry, a safe verified improvement, and signed upgrade
QA remain open. This is not a shipping Environment Brief or setup-session flow.
The subsequent [startup boundary](v0.20-first-run-startup-gate.md) now makes this
observer available before runtime activation; guarded UI entry remains pending.

## Why a Separate Path

The existing normal-operation endpoints cannot be used behind first-run's
local/no-change disclosure without additional work:

- `helm_trigger_detection` schedules remote catalog work after detection.
- Detection persistence can reconcile a selected executable path.
- `helm_list_manager_status` can probe versions, self-heal manager enablement,
  and persist Doctor results.

Those ordinary workflows remain unchanged. The new observer does not call them,
instantiate a process executor, or accept an operation request.

## Implemented Contract

- Core: `first_run::observe_first_run_environment` with explicit local search
  context and the existing read methods on `DetectionStore`.
- C: `helm_observe_first_run_environment`; JSON ownership follows
  `helm_free_string`, and unavailable/storage failures return null plus the
  existing error key, never a fabricated empty environment.
- XPC: `observeFirstRunEnvironment(withReply:)` forwards the same envelope.
- Envelope: `schema_version = 1`, `experience_id = wayfinder-v0.20`, one row for
  every supported manager, in `ManagerId::ALL` order.

Each row separates these facts:

| Field | Meaning |
| --- | --- |
| `configured_enabled` | Stored user preference, or null when unset; not effective eligibility or inferred consent. Disabled managers are not omitted. |
| `selected_executable_path` | Stored selection unchanged, even if missing or relative. |
| `candidate_paths` | Currently observed regular files at candidate paths. Not validated executables, install instances, or a readiness result. Aliases remain candidate paths, not multiple-install findings. |
| `candidate_scan_status` | `complete` means attempted candidates were inspected; `partial` means a scope limit, ignored relative path, or metadata error; `not_supported` means this limited scan has no candidate scope. None means a manager is absent or ready. |
| `inspected_path_count` | Number of unique absolute candidate paths attempted. |
| `cached_detection` | Prior detection, explicitly historical even if a candidate still exists at its old path; never promoted to current version/installation evidence. |

The automatic scope reads only candidate-file metadata plus Helm's existing
preferences and detections. It uses known bin locations, absolute environment
roots/PATH directories, and recorded manager paths. There are at most 64 search
directories and 256 candidate checks per manager. There is no recursive directory
walk, content read, subprocess, version probe, catalog/update check, task, package
mutation, preference repair, legal acceptance, or acknowledgment. Limits bound
the number of metadata checks, not OS filesystem response latency.

`xcode-select` alone is not a CLT candidate: its macOS stub does not establish
that developer tools are installed. Non-executable/dangling files, proxies and
aliases cannot establish a usable manager. App-backed and other unsupported
sources retain explicit unknown scope rather than a false Not Installed result.
No new user-visible strings or locale catalogs change in this slice.

## Activation Still Required

The endpoint is deliberately not wired into the existing Debug Brief or normal
poller. It cannot make ordinary startup safe merely by being present. The next
entry integration must:

1. Load versioned acknowledgment and legacy legal state before choosing a route;
   read failures stay unavailable and do not grant consent.
2. Prevent ordinary refresh/status/Doctor/self-heal work and automatic updater
   scheduling from racing first-run entry, preserving existing preferences.
   Use the subsequent two-step preparation/activation boundary, not direct
   `helm_init`, which intentionally retains normal CLI startup behavior.
3. After required legal acceptance, use local evidence honestly. Candidate files
   alone cannot populate Ready to Manage, current coverage, or action approval.
   Additional manager-backed discovery needs its own bounded, disclosed path.
4. Add the supported safe reviewed action with current-state revalidation,
   independent post-verification, honest receipt/recovery, and persisted completion.
5. Save acknowledgment successfully before leaving the real flow. Preserve
   preview isolation and run signed fresh/upgrade/offline/interruption QA.

The observer is not a transactionally consistent execution plan or a cached
authorization token. Any later action must revalidate its own authoritative
preconditions. Broader persisted setup/CLI parity remains v0.21 scope.

## Validation

Runtime checks run only in the disposable arm64 macOS VM, using isolated HOME,
TMPDIR and database paths under
`/Users/agent/helm-certification/first-run-observation-20260927/`.
Host work is compilation/static validation only; production Helm and its database
are untouched. No VM shutdown, manager installation, release, or publication.

The regression set covers all-manager/unset state, disabled preferences and stale
selected paths, cached/current separation, alias and broken-link semantics,
zero executable launches, scope/error reporting, no recursive traversal or CLT
stub inference, read failures, JSON/error/memory ownership, repeatability, and
no database commits/tasks/acknowledgment. Test fixtures use PID/time/counter IDs:
time alone collided on two parallel tests in the initial VM run and was corrected.

Validation on 2026-09-27 UTC:

- Eight targeted core regressions and one C-boundary integration regression pass
  in the VM; the full core library (803 tests) and FFI library (105 tests) pass.
- Host compilation of the arm64 app/service with a macOS 13.0 deployment target
  passes, including the new protocol method, implementation, and C export.
- Rustfmt, workspace/all-target Clippy with warnings denied, targeted strict
  SwiftLint, channel policy, docs-sync/release-line checks, and diff hygiene pass.
- Xcode retains the two known warning categories: no AppIntents metadata to
  extract, and the helper-stripping script phase without declared outputs.

Signed GUI/XPC runtime and genuinely CLT-free OS validation remain open;
compilation targeting macOS 13 is not a Ventura runtime pass. No claim is made
for the full workspace integration or Swift runtime suites in this bounded slice.
