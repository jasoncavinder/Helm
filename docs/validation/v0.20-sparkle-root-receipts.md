# v0.20 Root Installer Receipt Payloads

Date: 2026-10-17. Follow-up to #607 and the
[supported ownership scope](../architecture/EXTERNAL_SPARKLE_OWNERSHIP_SCOPE.md).
This closes the bounded root-payload omission, not complete ownership coverage.

## Change And Limits

The catalog previously skipped receipts installed at `/`. Current-tree file-info
queries cannot substitute for historical/deleted payload claims in those receipts.
The observer now queries the supported system `pkgutil --files <identifier>`
interface for every root-location receipt. Empty, `/` and `.` install locations
normalize to the same root; existing non-root export checks are unchanged.

A target or descendant payload is a competing-manager claim, including
case/Unicode-equivalent spellings. Shared ancestor directories such as
`Applications` are not claims on every app beneath them. Paths are interpreted
lexically, without probing destinations or executing manager/installer code.
Listings must be valid UTF-8 with complete newline framing, no blank lines,
absolute paths, traversal, control characters or paths longer than 4,096 bytes.
All paths are validated even after a match or when their prefix cannot match.
Embedded-newline ambiguity can add conservative denials, but cannot hide the
prefix of a child under an already validated newline-free target.

The new listing channel is bounded at 8 MiB per receipt, 32 MiB aggregate and
100,000 paths per receipt. Existing catalog/file-info 4 MiB bounds, per-query
timeouts and the shared three-second snapshot deadline are unchanged. Errors,
limits and timeouts reject the observation, never return partial unclaimed facts.
Empty successful output is retained, not interpreted as proof of script-free
installation or permission to adopt.

Each listing contributes a domain-separated SHA-256 digest of every raw byte,
receipt ID, byte/path counts and claim result. This compact value is carried
through receipt snapshot equality and the private ownership fingerprint introduced
by #643. Unrelated path changes are bound too; no large listing is retained in the
review. Both within-observation and later-review equality therefore see root
payload drift. The wire/ledger schema and acknowledgment scope are unchanged.

## Remaining Gates

Aliases, unobserved installer-script effects and unsupported cask artifact forms
remain coverage obligations. No complete-ownership value or standalone provenance
is inferred from an empty claim list. The production adoption provider remains
absent and direct updating stays disabled. Keep #606/#607/#608 open and Open App
available; next complete the supported native coverage, then authenticated
grant/session wiring and fresh signed lifecycle/recovery and GUI/CLI acceptance.
No licensing activation, signing configuration, release or website publication
is part of this change. No new manual owner UI QA is required for this slice.
