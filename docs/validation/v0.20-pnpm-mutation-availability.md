# v0.20 pnpm Mutation Availability

## Contract

The existing pnpm 11+ safety boundary now reaches the preview instead of only
appearing after an attempted package task. It does not add group-aware mutation
support or close #559. The upstream [global installation model](https://pnpm.io/cli/add#--global--g)
can associate packages that share removal/update scope; an individual Helm
checkbox does not consent to changing their peers.

`manager_policy::package_mutation_block_key` is shared by cached presentation and
the live adapter guard. Stable numeric pnpm versions 1 through 10 retain the
previous routes; versions 11+, prereleases, missing and unrecognized versions
remain blocked. This is not blanket certification of every legacy version.

- Manager-status capability Booleans intersect the existing surface allowlists
  with the version rule. `packageMutationServiceErrorKey` provides the localized
  explanation on both CLI/FFI payloads and GUI package/manager inspectors.
- Manager enablement/eligibility, reads, discovery, virtual pins and executable
  lifecycle authority are unchanged. Existing individual-action allowlists are
  not broadened; legacy pnpm GUI upgrades continue through Plan.
- FFI Plan rows retain their package identity, action and position, but carry
  `status: blocked` and the service guidance key as their reason. Old task state
  cannot mask that block. Selection, Select All, notification confirmation,
  automatic counts and retry exclude the blocked rows; they remain inspectable.
- CLI preview adds `runnable` and optional `blockedServiceErrorKey`. A known
  blocked run reports a non-success result without queuing a package task.
  Detached workflows apply the same rule. Other eligible steps still run.
- Reviewed FFI submissions reject newly blocked drift. Unreviewed/legacy bulk
  paths do not enqueue known-blocked pnpm work. The live adapter still rechecks
  the selected executable immediately before mutation; cached detection is
  advisory evidence, not authorization. Direct commands can still produce a
  useful failure task when the live installation changes after the snapshot.

## Remaining Acceptance

A same-source signed VM GUI check must verify the blocked row, unselectable
checkbox/Select All behavior, inspector guidance and keyboard/VoiceOver/live
localization. These new visual semantics are not covered by the earlier accepted
failed-task diagnostic check. Group-aware pnpm support and its release disposition
remain separate work under #559.
