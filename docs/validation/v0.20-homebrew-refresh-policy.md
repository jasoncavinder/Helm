# Delegated Homebrew Refresh Policy

Follow-up to [#603](https://github.com/jasoncavinder/Helm/issues/603), based on
merged #616 (`63a210d4`). The tested product working tree is recorded by commit
`0b8451cc`. This extends #605's [named-outdated correction](v0.20-named-homebrew-outdated.md),
not its acceptance of arbitrary nonzero output.

## Reproduction and Contract

Signed first-run QA exposed two remaining cases in Docker Desktop and Podman
refreshes: an implicit `brew update` lock conflict, and valid exit-1 outdated
results accompanied by API-download progress on stderr. Colima uses the same
delegated command path. Unlike the regular Homebrew process sources, all three
omitted Helm's no-auto-update environment policy.

The disposable macOS 27 arm64 VM reproduced a cold-cache native Podman query on
Homebrew commit `d6ca355094` with captured stdout and stderr. It returned exactly
Podman 6.1.2 -> 6.1.3, exit 1, and only a download heading plus a successful
`JSON API packages.arm64_golden_gate.jws.json` report. A warm-cache query returned
the same JSON with empty stderr. Adding `--quiet` is not a solution: Homebrew
rejects it together with `--json`; that failed probe is retained.

- Delegated `brew info` and `brew outdated` now set `HOMEBREW_NO_AUTO_UPDATE=1`,
  `HOMEBREW_NO_INSTALL_CLEANUP=1` and `HOMEBREW_NO_ENV_HINTS=1`, matching the
  regular Homebrew sources. Native Podman/Colima version probes are unchanged.
  This prevents implicit Homebrew checkout updates, not every metadata-cache
  write/download; absent API data can still be fetched. The caller's explicit
  `HOMEBREW_FORCE_API_AUTO_UPDATE` override is not rewritten.
- The existing exit-1 exception still requires the exact manager, action,
  executable basename, arguments, collection/name and complete version evidence.
  It now admits only empty stderr or a bounded complete successful API report:
  the exact heading and one or more success-marked JSON API metadata filenames.
  Recognized files are formula/cask signed JSON or arm64/x86_64 platform signed
  package JSON with a bounded ASCII platform token. No paths, extra diagnostic
  text, unknown files, failed markers, invalid UTF-8 or partial reports pass.
- Lock errors, network errors, warnings (including stale-cache warnings), unknown
  diagnostics and malformed/unrelated/empty exit-1 results remain failures.
  Other nonzero statuses, signals, timeout/cancellation, process context and
  strict `brew info` status handling are unchanged. No broad stderr discard,
  retry, process killing, scheduler-lock change or mutation capability is added.

Upstream references: [Homebrew environment controls](https://docs.brew.sh/Manpage#environment),
[API cache/download behavior](https://github.com/Homebrew/brew/blob/d6ca355094/Library/Homebrew/api.rb),
and [download reporting](https://github.com/Homebrew/brew/blob/d6ca355094/Library/Homebrew/download_queue.rb).
