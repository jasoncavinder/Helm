# External Sparkle Helper Self-Identity

Status: local native prerequisite for [#607](https://github.com/jasoncavinder/Helm/issues/607),
not an operational helper or an enabled direct-update capability. Based on merged
#617 (`223a22f6`); tested implementation commit `38730d72`. The original
vendor-app handoff is unchanged.

## Contract

`NativeHelperObserver.observeSelf()` accepts no path, PID, signing requirement,
channel, notarization Boolean or claimed authority from an XPC client.

- Reject root/setuid accounts before inspecting code; repeat account observation.
- Obtain the live process with `SecCodeCopySelf` and apply the existing fixed
  helper code requirement, including exact identifier/team, Developer ID signing,
  notarization and exclusion of sandbox/debug injection entitlements.
- Obtain secured signing information from Security.framework, never CFBundle's
  display dictionary. Require the exact helper identifier/team, a bounded build
  and executable name, APPL bundle type and signed `developer_id` channel.
- Require the hardened-runtime bit in both signed flags and live process status.
  The initial helper needs no entitlements: missing or empty entitlement maps
  pass, while any grant or undecodable raw entitlement data fails closed. New
  helper entitlements require separate review, not silent policy relaxation.
- Use the native code path, reject non-app/symlink paths, check a freshly created
  static code object with strict/all-architecture/nested-code validation, and
  compare its sealed metadata/hash with the live code. Recheck live validity.
- Recollect the entire snapshot and reject changed account, path, device/inode,
  bundle change timestamp, build, executable, signature hash or flags.
- Return Encodable-only local evidence with no public constructor and no
  `authorized`, `eligible` or caller-claimed `notarized` result. There is no cache
  or fallback after failed observation. Test capture injection is Debug-only.

Security.framework explicitly accepts dynamic code objects in the static-typed
signing-information/path APIs. The documented type bridge preserves live status;
converting first with `SecCodeCopyStaticCode` would lose that dynamic evidence.
The API also warns that locating a disk origin is not a secure binding by itself,
which is why this collector checks live validity and a fresh disk object rather
than trusting the returned path alone. Native trust evaluation remains under
macOS control; no network-suppression flag that weakens trust checking is set.

This remains a snapshot, not a filesystem lock. It does not inspect helper parent
ACLs, prove launch-time sandbox inheritance, package the helper, validate its
loaded Sparkle framework, authenticate a caller, resolve target manager authority,
or populate the complete shared-core boundary observation. Those operational
requirements remain open. Re-observe before review/confirmation in the future
runtime rather than persisting this snapshot as reusable authorization.

## Verification

Unsigned compilation on the host; runtime execution only in the disposable
macOS 27 arm64 VM, with isolated HOME/temp/database paths.

- All **49 package tests** pass: 11 new helper-identity tests plus the existing
  38 observer, peer and bootstrap tests.
- The real production observer rejects the unsigned XCTest host through the
  native fixed requirement. Positive snapshot/metadata cases are injected test
  fixtures, **not** acceptance of a signed/notarized helper.
- Tests cover root/setuid and account drift, second-observation failure, identity/
  filesystem drift, no cached success, exact identifier/team/channel, bounded
  metadata, missing/malformed hashes, hardened runtime and entitlement rejection.
- Debug test compilation, Release package compilation and strict source SwiftLint
  pass. No runtime test or QA app is launched on the host. No package operation,
  GUI replacement, signing, notarization or publication is performed.

Evidence is retained under the task worktree's ignored `artifacts/` and guest
`/Users/agent/helm-certification/sparkle-helper-identity-20261002/`.

exclude those build artifacts. These harness attempts are not product failures.

and candidate mapping, durable-session integration, Ventura/Intel runtime and
real download/install/relaunch/cancellation/recovery remain release gates. This
slice does not close #606 or #607 and does not require repeating accepted owner
