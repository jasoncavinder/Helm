## Scope and Safety

All live commands run in the supplied arm64 macOS 27 guest, never against the
owner's host tools or stable database. The shared fixture uses
`~/helm-certification/campaign/{home,helm.db}` with explicit HOME, XDG paths,
package prefixes and `HELM_DB_PATH`. MacPorts/Rosetta administrative scenarios
use a separate `admin-campaign` HOME/database. Those administrative CLI tests do
not certify the GUI authorization prompt or the privileged-helper boundary.

Evidence is retained as timestamped JSON command envelopes under each fixture's
`evidence/` directory. Each ordinary CLI envelope includes binary SHA-256,
arguments, exit status, stdout/stderr and elapsed time. The initial family binary
at this checkpoint was a local Debug CLI built from the uncommitted family
corrections on top of `fd209d37`, SHA-256
`af089aadaeb4b0e4aaf880c0777b26a5b685594b304a89ed32c9a22aa93f9823`.
Earlier runs use the hash in their own envelope; do not attribute them all to
this binary. The uv endpoint evidence retains its separate hash and fixture.
The final read sweep, fresh pnpm 10 lifecycle, controlled MacPorts upgrade and
rustup current-stable check use the later local Debug CLI built from `2d388caf`
plus the then-uncommitted pnpm empty-scope correction, SHA-256
`cd6113082bb3e00594df10b808d94c33d1411066be13c1d74ff5cc40bb022529`.
The subsequent pnpm safety-boundary run and legacy lifecycle recheck use Debug
CLI built from `962127b6` plus the then-uncommitted mutation guard, SHA-256
`404907bad3ba3d500c66181355a0d5bd4f93ce3f1e43bfa3d9d53324fa125853`.

“Lifecycle” below means bounded package install, inventory, outdated discovery,
Helm/native pin exclusion, unpin, targeted upgrade and removal. It does not imply
every manager installation method, cancellation, authenticated repository,
supported macOS release, GUI flow or package type has been certified.

## Findings Corrected in This Branch

- asdf 0.20 emits `asdf version ...`; detect must not report `version` as its version.
- cargo-binstall uses `-V` for its version; `--version` is a package-version argument.
- Bundler 4 emits a bare version. Its RubyGems outdated output uses `current < latest`.
- npm's never-created global prefix is empty, not a failed inventory. Only verified
  missing roots qualify; existing, inaccessible or dangling paths do not.
- pnpm 10's never-created global project reports a missing-manifest diagnostic,
  not JSON. Only that exact exit-1 diagnostic, no stderr, a successful selected
  `pnpm root -g` lookup and filesystem-confirmed project absence qualify as empty.
  Existing, dangling, inaccessible and mismatched scopes remain errors; no store
  is created during refresh. This is separate from pnpm 12's native upgrade no-op.
- Yarn Classic inventory/outdated queries must run in `yarn global dir`, not the
  caller's project. Inventory excludes hoisted transitive dependencies. Fresh empty
  scopes avoid missing-lockfile errors, and registry/JSON errors remain failures.
  Classic has no registry `search` command: Helm now performs exact-name lookup via
  `yarn info NAME version --json`, retaining Yarn's configured registry.
- pnpm and Yarn targeted upgrades request latest versions rather than remaining
  constrained to the originally installed version. pnpm 11+ has a separate
  mutation safety boundary below; this is not a claim that its update issue is fixed.
- pnpm 11+ install groups can remove or change packages beyond the individually
  selected item. Helm now blocks install, targeted/bulk upgrade and removal on
  those versions, prereleases and unrecognized versions before mutation. Reads
  and virtual pins remain available. Legacy bulk updates also verify that no
  outdated candidates remain instead of trusting only a successful process exit.
- Poetry checks `self show --addons --outdated`, filters to plugins, and upgrades
  plugins with `self add NAME@latest`; `self update NAME` targets Poetry itself.
- pipx actually requests outdated metadata, parses the current versioned result
  envelope, preserves environment identity/native pins, and reconciles observed
  installed/removed identities. SQLite-backed removal regression prevents ghosts.
- Explicit executable selection retains the invocation symlink. Detection and
  execution resolve the same selected executable, including sibling entrypoints.
  Python venvs have distinct identities and do not inherit base-interpreter
  ownership. Detection reconciliation prefers the exact selected display path
  over another instance sharing its canonical interpreter.
- CLI uninstall now accepts `--version` for asdf, mise, RubyGems, Bundler and
  MacPorts. Ambiguous multi-version removal remains blocked; unversioned managers
  reject the flag rather than ignoring it. This exposes an existing backend input.
- Homebrew formula inventory retains tap-qualified `full_name`, matching outdated
  identity; unqualified aliases resolve only when unambiguous. Install, pin,
  upgrade and removal reconcile the same observed package identity.
- Homebrew cask inventory accepts current scalar installed versions as well as
  legacy arrays. Cask mutations delegate Helm's validated askpass helper to
  Homebrew's own privileged subprocesses; Homebrew itself never runs as root.
- Docker Desktop detects the current bundled `Contents/Resources/bin/docker`
  entrypoint. nix-darwin detects `darwin-rebuild --help` without inventing a
  version from its help banner or treating plain `nix` as another installation.
- pipx update discovery explicitly requires stable 1.16.0 or newer, the native
  `list --outdated` capability. Older/unknown versions fail with upgrade guidance,
  not an empty-success result or an alternate package-index fallback.
- RubyGems interactive search requests compact `--no-details` output rather than
  downloading a gemspec for every match. The broad `rake` query previously hit the
  extended 90-second deadline; the corrected full search sweep passes. Registry
  configuration remains owned by RubyGems; summaries are absent when not returned.

### pnpm Install-Group Safety Boundary

The pnpm-only reduction `pnpm12-reduction-1790340804672867000` compares fresh
separate installs and a native comma-separated group containing prettier 3.5.3
and semver 7.6.3. Both targeted and bulk native `update -g --latest` exit zero
without applying candidates 3.9.9/7.8.5. More importantly, native removal of
prettier removes semver too when grouped, while the separate-install case retains
semver. No Helm code runs in this reduction. This removal is documented
[pnpm v11+ group behavior](https://pnpm.io/global-packages), not an upstream bug;
Helm's individual selection/pin model does not authorize its collateral changes.

The conservative shared-adapter guard covers **all** mutations on 11+, including
single-package groups, and unknown/prerelease versions. It does not downgrade,
reinstall, override registry policy, disable the manager or hide update candidates.
This is a safe compatibility limit, not completed support for the new model.

excluded from preview, install/upgrade/removal each return the exact safety
diagnostic, and native/Helm inventories retain **both** original grouped packages

nonzero exit. The legacy recheck `pnpm10-fresh-1790341593624274000` passes fresh-store refresh,
install, pin exclusion, real 3.5.3-to-3.9.9 upgrade and removal on 10.16.1 with
