## Scope and Safety

All live commands run in the supplied arm64 macOS 27 guest, never against the
owner's host tools or stable database. The shared fixture uses
`~/helm-certification/campaign/{home,helm.db}` with explicit HOME, XDG paths,
package prefixes and `HELM_DB_PATH`. MacPorts/Rosetta administrative scenarios
use a separate `admin-campaign` HOME/database. Those administrative CLI tests do
not certify the GUI authorization prompt or the privileged-helper boundary.

Evidence is retained as timestamped JSON command envelopes under each fixture's
`evidence/` directory. Each ordinary CLI envelope includes binary SHA-256,
arguments, exit status, stdout/stderr and elapsed time. The latest family binary
at this checkpoint is a local Debug CLI built from the uncommitted family
corrections on top of `c5637e35`, SHA-256
`eda16bb1a1d472147fc442bb110fa15615fc028192d1a423102205eb258e9978`.
Earlier runs use the hash in their own envelope; do not attribute them all to
this binary. The uv endpoint evidence retains its separate hash and fixture.

“Lifecycle” below means bounded package install, inventory, outdated discovery,
Helm/native pin exclusion, unpin, targeted upgrade and removal. It does not imply
every manager installation method, cancellation, authenticated repository,
supported macOS release, GUI flow or package type has been certified.

## Findings Corrected in This Branch

- asdf 0.20 emits `asdf version ...`; detect must not report `version` as its version.
- cargo-binstall uses `-V` for its version; `--version` is a package-version argument.
- Bundler 4 emits a bare version. Its RubyGems outdated output uses `current < latest`.
- npm's never-created global prefix is empty, not a failed inventory. Only verified
  missing roots qualify; existing, inaccessible or dangling paths do not.
- Yarn Classic inventory/outdated queries must run in `yarn global dir`, not the
  caller's project. Inventory excludes hoisted transitive dependencies. Fresh empty
  scopes avoid missing-lockfile errors, and registry/JSON errors remain failures.
  Classic has no registry `search` command: Helm now performs exact-name lookup via
  `yarn info NAME version --json`, retaining Yarn's configured registry.
- pnpm and Yarn targeted upgrades request latest versions rather than remaining
  constrained to the originally installed version. pnpm 12 has a separate open
  upstream-behavior boundary below; this is not a claim that it is fixed.
- Poetry checks `self show --addons --outdated`, filters to plugins, and upgrades
  plugins with `self add NAME@latest`; `self update NAME` targets Poetry itself.
- pipx actually requests outdated metadata, parses the current versioned result
  envelope, preserves environment identity/native pins, and reconciles observed
  installed/removed identities. SQLite-backed removal regression prevents ghosts.
- Explicit executable selection retains the invocation symlink. Detection and
  execution resolve the same selected executable, including sibling entrypoints.
  Python venvs have distinct identities and do not inherit base-interpreter
  ownership. Detection reconciliation prefers the exact selected display path
  over another instance sharing its canonical interpreter.
- CLI uninstall now accepts `--version` for asdf, mise, RubyGems, Bundler and
  MacPorts. Ambiguous multi-version removal remains blocked; unversioned managers
  reject the flag rather than ignoring it. This exposes an existing backend input.

## Open Safety Gates

Two concurrently started CLI processes exposed duplicate persisted task IDs.
The correction adds migration 21's durable high-water mark and atomically reserves
queued records before execution. Regression coverage includes independent
processes, concurrent runtimes, deletion without ID reuse, exhaustion and failed
reservation with no execution. Migration compatibility and a live concurrent CLI
rerun must pass before closing this gate. This does not add cross-process manager
execution leases or authorize concurrent mutations in the same tool environment.

Helm launch/read-only operation must not acquire a blanket CLT requirement.
The initial CLT prompt came from test-Python bootstrapping, not proof that Helm
requires CLT. Source compilation and some manager installers do require developer
tools; operation-specific preflight and actionable prerequisite UX remain open.
No CLT-free runtime certification has yet been obtained after installing CLT.

Full Rust workspace tests, formatting and Clippy are the required code gates.
The live evidence complements, rather than replaces, parser/process/persistence
regressions. Keep #500/#526 open and do not merge the campaign PRs yet.
