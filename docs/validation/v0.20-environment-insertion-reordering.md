# v0.20 Environment Insertion Reordering

Date: 2026-09-27 UTC. Base: merged `dev` `35a91885`.
Status: implementation and automated checks complete; signed interaction QA
pending under #464. This is not permission to close the issue or waive RC gates.

## Behavior

- Drag a detected manager's leading handle. Its card becomes a same-height,
  localized insertion placeholder that moves before/after eligible target cards.
  The pointer preview names the manager; there is no duplicate source card.
- Preview never writes priority. A valid drop revalidates the original installed
  order, authority and membership before committing through the existing local
  priority persistence path. Changes during a drag invalidate it rather than
  overwriting newer preferences or detection state.
- Cross-authority and not-installed targets are rejected. Not-installed managers
  have neither a drag source nor reorder menu. Unmoved managers retain relative
  order, including hidden managers when a route filter is active.
- Native drag completion covers Escape, invalid/outside drops and view departure.
  Stale completion callbacks cannot cancel a newer session. No background window
  dragging, package mutation, enablement change or backend authority-policy change.
- A native Move Up/Move Down menu provides the non-pointer path through the same
  validated order commit. Boundary actions are disabled. Existing Restore Default
  remains in Settings. The menu and placeholder are localized in seven locales.
- Native document autoscroll is requested during an active drag near the list
  boundary. No reorder animation is added, including under Reduce Motion.

## Owner Refinement: Edge Overlap

During integrated VM QA on 2026-09-30 the owner confirmed the basic placeholder
interaction works, but requested earlier movement and reported literal braces
around the manager name. This does not accept the remaining ordering checks.

The preview now uses the native dragged image's bounds against installed cards,
rather than waiting for the cursor to reach a target's vertical midpoint.
Downward overlap inserts after the card; upward overlap inserts before it.
Geometry is measured in scroll-document coordinates, including during autoscroll.
Stationary layout changes are not new drag motion; a four-point direction-reversal
tolerance prevents small pointer jitter from immediately undoing a move. Existing
authority, membership, stale-order and drop-commit checks remain unchanged.

All seven canonical and bundled translations use the formatter's single-brace
`{manager}` token. The rendered placeholder must not contain literal braces.
Added regressions cover early upward/downward overlap, stationary reflow and
reversal, filtered/fast movement, horizontal misses, invalid geometry, foreign
authority/stale tokens, cancellation reset and seven-locale interpolation.

Signed native interaction acceptance of this refinement is pending. Recheck
early overlap in both directions, stationary stability, cancellation and the
remaining required acceptance below; unit tests do not certify AppKit delivery.

## Required Signed VM Acceptance

1. In Environment, drag an installed manager within its authority group. Confirm
   exactly one correctly sized placeholder follows before/after targets, and the
   final drop persists across reopening. Missing-manager cards cannot initiate
   or accept reordering, and other authority groups reject the drop.
2. Drag and press Escape; repeat with a drop outside Helm. Confirm the original
   order returns and no placeholder remains. Repeat after filtering/unfiltering.
3. With a long group, hold near the scroll boundary. Confirm autoscroll continues
   while stationary and stops after drop/cancellation. Test top/bottom endpoints.
4. Use keyboard and VoiceOver to open each card's reorder menu and Move Up/Down;
   confirm focus remains usable, boundary items disable correctly, and the result
   matches pointer ordering. Recheck light/dark, Reduce Motion, long localized
   labels and minimum-size/inspector-open layouts.

This list is new interaction acceptance, not a request to repeat unrelated owner
checks. Unit tests do not establish native drag destination geometry, signed
AppKit/SwiftUI delivery, autoscroll or assistive-technology behavior.
