## Observed Defect

completed, the GUI/CLI/native inventory agreed on `helm-uv-smoke` 1.1, its
requirements/Python/entrypoints were preserved, and the peer stayed at 1.0.

The preview correctly reported `managerAutomationLevel: read_only` and
`managerUninstallStrategy: read_only` for the uv executable. The GUI incorrectly
used that manager-lifecycle metadata to replace the package confirmation with
an informational-only dialog. The TUI had the same conflation; ordinary CLI
package execution did not use that guard. The adapter was not reached.

## Correction

- The GUI confirmation uses the existing `canUninstallPackage` capability,
  enabled-manager and installed-state checks, as the action itself already does.
- The TUI confirmation uses cached manager status's package-uninstall capability
  and effective enablement, including shared version-specific mutation blocks.
- Manager executable removal remains read-only. No uv lifecycle authority,
  provenance override or package execution permission is added.
- Core runtime capability, scope/receipt, version and post-action checks remain
  authoritative. A confirmation preview never substitutes for those checks.

Regression coverage checks the production Swift confirmation/action wiring and
the real TUI preparation path with a read-only uv install instance. Disabled uv,
unsupported Setapp removal and version-blocked pnpm remain unavailable.
