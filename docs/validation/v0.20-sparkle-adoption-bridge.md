# Private Sparkle Adoption Bridge

Date: 2026-10-04. Base: `fa083770` (#631, including merged #629).
Scope: private in-process bridge prerequisite for #607; #606/#608 remain open.

## Contract

The private C ABI connects fresh native target/boundary observations to
`ReviewedLedgerAdoption`, not the general migrating store. It accepts the strict
bounded adoption intent separately from local evidence. Unknown fields, malformed
strings, oversized input, null required pointers, unsupported ABI versions and
unknown/missing boundary flags fail closed. Fixed helper/caller identities and
teams remain enforced by core. This bridge transports facts; it does not collect
or authenticate them.

The boundary layout carries all six facts explicitly: live authenticated caller,
valid Developer ID signatures, accepted notarization, preserved Helm sandbox,
unsandboxed external helper and direct-consumer channel. No missing fact defaults
to success. A hello or absent entitlement is not evidence of inherited sandbox
state. The existing target mapping still maps absent manager markers to Unknown,
never Standalone or UserAdopted. Complete supported ownership observations remain
a native-coordinator obligation; an empty exclusion list is not that proof.

Preparation reads an existing ledger and returns an opaque owned review, never
an IPC token. Confirmation consumes it on every outcome and maps results to:

- `51`: per-app consent recorded, not update approval.
- `52`: changed/rejected review; no grant from this attempt.
- `53`: outcome unknown; never automatic retry consent.

The internal, worker-confined Swift owner clears its handle before confirmation,
frees abandoned reviews, and consumes attempts rejected before C entry because
of target-mapping failure or account-root drift. It cannot be reused. Boundary
inputs are not Codable and have no public Swift initializer; no production caller
currently supplies them. Existing preflight/history/revocation behavior and codes
are preserved. Even after a synthetic grant, preflight remains unresolved and
returns no update token.

This adds no XPC adoption method. Before exposing one, the native coordinator must
collect fresh trusted evidence, hold the existing-only filesystem lease around
each operation, bind the review to one authenticated connection, admit a live
confirmation once, and recheck identity/lease/session state before publishing
success. Storage errors, failed postchecks or lost replies require fresh history
and a new human decision, not replay. Adoption and each update remain separate
consent decisions.
