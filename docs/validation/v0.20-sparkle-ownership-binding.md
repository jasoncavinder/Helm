Date: 2026-10-17. Follow-up to #607 and the

## Change And Safety Boundary

Previously, native observation compared raw receipts and registry replies within
each scan, but retained only their summarized claims/gaps in the returned target.
Two separately stable scans could therefore compare equal during adoption review
despite changes to the underlying ownership evidence.

The observer now computes a domain-separated, version-1 SHA-256 fingerprint after
its existing revalidation succeeds. It binds scope version 1, target/application
roots, scanned cask roots, MacPorts registry path, inspected bundle identities,
and the complete bounded Homebrew/installer/MacPorts snapshot values. Raw bytes
are encoded as data, not parsed and normalized; sorted dictionary keys and JSON
array/data boundaries avoid insertion-order and concatenation ambiguity.

The fingerprint participates in native target equality, not diagnostic JSON.
Missing fingerprints reject before the coordinator opens storage. The direct
Swift adoption bridge also requires one and holds the full reviewed native target
for confirmation. Evidence drift consumes the single-use confirmation; drift
observed after possible commit remains `outcomeUnknown`, never safe automatic
retry. The Rust ABI, ledger schema and existing scope acknowledgment are unchanged.

The fingerprint is not a client input, public/Decodable construction API, stored
permission or complete-ownership assertion. Production adoption stays disabled;
unknown ownership remains unresolved. No new source is scanned, no artifact gap
is waived, and no `SPUUpdater` or installation path is enabled.
