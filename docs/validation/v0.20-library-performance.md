# v0.20 Library Performance Validation

Status: Slice 20.3 automated performance gate passed on 2026-08-19

## Scope

This record covers the production local/cached Library derivation and native-table scroll-critical path required by Slice 20.3. It does not claim remote-manager latency, display-compositor timing, or the milestone-wide Instruments pass required by v0.22.

The deterministic stress fixture contains:

- 30 software sources;
- 20,000 distinct consolidated package rows;
- a broad `package` query that returns all 20,000 rows;
- 30 cold complete derivations;
- 30 warm indexed derivations; and
- 120 viewport moves through the production `NSTableView`, including visible-cell realization and AppKit layout/display work.

The benchmark starts Helm in an inert Debug-only mode before updater, service, database, network-monitor, or UI startup. `HELM_DB_PATH` still points to an isolated test path. Release builds ignore the benchmark environment key.

## Reproduction

Run the checked-in harness from the repository root:

```bash
scripts/tests/library_performance_budget.sh
```

The script builds `arm64` Debug with `SWIFT_OPTIMIZATION_LEVEL=-O`, keeps profiling output under the temporary directory, runs at least 30 iterations, emits one `HELM_LIBRARY_BENCHMARK` JSON line, and fails unless all encoded budgets pass. `HELM_LIBRARY_BENCHMARK_ITERATIONS` may be set from 30 through 100.

## Test Conditions

- MacBook Pro `Mac17,6`
- Apple M5 Max, 18 CPU cores, 64 GB memory
- macOS `26.6.1` (`25G76`)
- AC power, battery at 100 percent
- Xcode SDK `26.5`; application deployment target macOS 13
- arm64 optimized Debug build, code signing disabled
- isolated database path `/tmp/helm-v020-library-benchmark.sqlite`
- offscreen `1000x620`-point AppKit table viewport; the scroll sample measures cell realization/layout/display calls rather than WindowServer compositor frames
- the same host's current visual matrix records the built-in Retina display at `2x` and an available `1x` external display; no result below is attributed to display-compositor timing

## Results

The unindexed production baseline performed repeated locale sorting, query normalization, merge-dictionary construction, and consolidation on every search. Thirty optimized-build samples measured `446.458/452.051/453.156 ms` median/p95/worst for the broad query.

The final indexed implementation measured:

| Metric | Median | p95 | Worst | Budget | Result |
|---|---:|---:|---:|---:|---|
| Cold index build + complete 20,000-row result | 78.545 ms | 80.650 ms | 81.840 ms | complete local/cached p95 <=150 ms | Pass |
| Warm broad local search | 10.406 ms | 10.589 ms | 10.658 ms | median <=50 ms; p95 <=100 ms | Pass |
| Native-table scroll-critical sample | 8.857 ms | 9.840 ms | 32.377 ms | >=95% <=16.7 ms; worst <=50 ms | Pass |

The scroll run placed 119 of 120 samples at or below `16.7 ms` (`99.17%`) and retained 12 AppKit row views while traversing a 20,000-row model. The focused automated table test independently verifies that a distant row remains unrealized and the visible viewport stays bounded.

## Implementation Contract

- Authoritative package changes, manager capability changes, manager-priority changes, and locale changes invalidate or rebuild the cached index.
- The index precomputes normalized identity, manager, and summary search fields and reuses unchanged consolidated rows.
- Query, manager, status, and pin filters remain member-scoped before consolidation.
- Pinned upgrades remain excluded from the Upgradable filter, while the Installed filter continues to include upgradable installed packages.
- Remote results retain the existing merge path, so the local index does not weaken progressive remote provenance or cancellation ownership.
- Library focus no longer constructs a 20,000-ID observation array on every SwiftUI render; pending focus is still reconciled when the displayed table state changes.
