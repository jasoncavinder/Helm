# v0.20 Library Performance Validation

Status: Slice 20.3 automated performance gate passed on 2026-08-19

## Scope

This record covers the production local/cached Library derivation and native-table scroll-critical path required by Slice 20.3. It does not claim remote-manager latency, display-compositor timing, or the milestone-wide Instruments pass required by v0.22.

The deterministic stress fixture contains:

- 30 software sources;
- 20,000 distinct consolidated package rows;
- a broad `package` query that returns all 20,000 rows;
- one same-ID manager-search overlay that must enrich exactly one retained local member;
- mixed Install, Unpin, Upgrade, and in-flight action states across the full result;
- 30 cold complete derivations and production projection-cache misses;
- 30 warm indexed derivations and production projection-cache hits; and
- 120 viewport moves through the production `NSTableView`, including visible-cell realization and AppKit layout/display work.

The benchmark starts Helm in an inert Debug-only mode before updater, service, database, network-monitor, or UI startup. `HELM_DB_PATH` still points to an isolated test path. Release builds ignore the benchmark environment key.

## Reproduction

Run the checked-in harness from the repository root:

```bash
scripts/tests/library_performance_budget.sh
```

By default, the script creates and reports one unique retained temporary root for DerivedData, the isolated database, and profiling output. It builds `arm64` Debug with `SWIFT_OPTIMIZATION_LEVEL=-O`, waits for three consecutive acceptable load/thermal/AC-power samples, runs at least 30 iterations, emits one `HELM_LIBRARY_BENCHMARK` JSON line, and fails unless all encoded budgets pass. A host that does not become ready within the bounded wait emits `HELM_LIBRARY_BENCHMARK_INVALID_ENVIRONMENT` and exits `75` instead of reporting a product failure. `--run-only`/`--reuse-built-product` requires an explicit app-binary or DerivedData override. `HELM_LIBRARY_BENCHMARK_ITERATIONS` may be set from 30 through 100.

## Results

The unindexed production baseline performed repeated locale sorting, query normalization, merge-dictionary construction, and consolidation on every search. Thirty optimized-build samples measured `446.458/452.051/453.156 ms` median/p95/worst for the broad query.

The final indexed implementation measured:

| Metric | Median | p95 | Worst | Budget | Result |
|---|---:|---:|---:|---:|---|
| Cold indexed derivation + complete 20,000-row result | 132.928 ms | 135.458 ms | 136.571 ms | complete local/cached p95 <=150 ms | Pass |
| Cold production projection/cache apply through first visible cells | 59.494 ms | 60.650 ms | 71.926 ms | p95 <=350 ms | Pass |
| Cold query-to-first-visible end to end | 192.575 ms | 195.415 ms | 208.498 ms | p95 <=500 ms | Pass |
| Warm indexed broad search | 22.365 ms | 24.332 ms | 25.180 ms | median <=50 ms; p95 <=100 ms | Pass |
| Warm production query/cache/apply through first visible cells | 27.604 ms | 30.273 ms | 30.521 ms | p95 <=100 ms | Pass |
| Native-table scroll-critical sample | 12.772 ms | 14.037 ms | 43.616 ms | >=95% <=16.7 ms; worst <=50 ms | Pass |

The run projected 20,000 actionable rows: 5,000 Install, 5,000 Unpin, and 10,000 Upgrade identities, including 1,177 in-flight rows. It applied the same-ID overlay exactly once, recorded 30 cold shared-cache misses and 30 warm shared-cache hits, placed 117 of 120 scroll samples at or below `16.7 ms` (`97.5%`), and retained 13 AppKit row views while traversing the model. The focused automated table test independently traverses the first, middle, and final viewports and verifies reused action/progress/accessibility state plus the retained-row bound.

## Implementation Contract

- Semantic authoritative-package changes invalidate the cached index; unchanged installed/outdated/cached/search publications do not. Manager disabled-membership, manager-priority, and locale changes invalidate or rebuild the affected projection.
- The index precomputes normalized identity, manager, and summary search fields and reuses unchanged consolidated rows.
- Fast folded-key ordering is accepted only after adjacent validation against the exact locale-aware deterministic comparator; any inversion falls back to that authoritative comparator.
- Query, manager, status, and pin filters remain member-scoped before consolidation.
- Pinned upgrades remain excluded from the Upgradable filter, while the Installed filter continues to include upgradable installed packages.
- Nonempty manager-search results use a revisioned, bounded overlay on the cached local index. Same-ID metadata enrichment retains the local member's identity/provenance, cross-manager identities reconsolidate only touched groups, and new identities merge into locale order without weakening progressive-search cancellation ownership.
- Production and benchmark use the same row projector and projection-cache identity. Package/member facts, selected source, manager preference/capability, action/in-flight state, updater availability, network state, and locale mutations miss the cache; unchanged semantic inputs reuse the snapshot revision so the Coordinator avoids full-array equality, dictionary rebuilding, and reload.
- The gate requires the production action mix, in-flight rows, one applied overlay, exact cold-miss/warm-hit counts, and no more than 20 retained row views; these are pass criteria rather than informational counters.
- Library focus no longer constructs a 20,000-ID observation array on every SwiftUI render; pending focus is still reconciled when the displayed table state changes.
