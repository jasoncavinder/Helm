# v0.20 Authority Overlap Test Stabilization

Date: 2026-09-27. Test-only correction; runtime authority ordering, concurrency,
manager policy and release gates are unchanged.

## Reproduction

During the isolated Cargo plan-binding validation, two broad VM runs failed
`parallel_within_authoritative_phase`, while its isolated rerun passed. The
fixture counted active adapter calls around a 50 ms sleep. Delayed scheduling
or persistence could prevent that short observation window from overlapping
even when the runtime correctly permits parallel managers.

A controlled regression delays one fixture adapter's entry by 250 ms and gives
both adapters zero simulated work time. With the old probe the test fails in the
VM, showing that the observation window, not package-manager behavior, controls
the assertion.

## Correction

- Hold the first probe entrant until a second entrant is actually observed.
- Protect the observed latch with a mutex/condition variable; do not rely on an
  increased sleep interval, wall-clock speed assertion, or unbounded barrier.
- Bound the wait to five seconds. A serial-execution regression returns an
  adapter error and fails the existing success assertions instead of hanging.
- Retain the peak-concurrency and both-manager completion assertions.
- Add a direct negative check: two serial entries each time out, never recording
  overlap. Other fixture delays and production code remain unchanged.

## Validation

Host preparation compiles tests and runs static checks only. Runtime verification
uses the disposable macOS 27 arm64 VM with isolated HOME/TMPDIR/database paths.
Evidence is retained under `helm-certification/authority-overlap-20260927` and the
task worktree's ignored `artifacts/`. The owner production Helm is untouched.

The delayed-entry regression fails before the correction. All eight authority
tests then pass 30 consecutive full-suite VM runs with four test threads (240
passing test executions). Targeted Clippy with warnings denied, rustfmt,
whitespace and docs-sync checks pass.

This narrows a test-harness race; it does not certify other operating systems or
close an adapter/release issue.
