   be readable/selectable, and source counts must describe observed files rather
   than claim every source is installed, working or healthy. The agent verifies
   that no ordinary manager/catalog task or self-update check ran before consent.
2. **Pre-v0.20 upgrade:** the introduction must still appear even with old
   onboarding completed. Quit before continuation and relaunch the same scenario:
   it must appear again. Select Use Helm Now, then quit/relaunch: it must not
   repeat. Existing language, manager choices, safe mode and consent must remain
   unchanged except for actions explicitly accepted in the flow.
3. **Repair review without mutation:** in the agent-prepared repair scenario,
   select Review a local repair. Check both full executable paths, the limited
   scope and verification explanation. Select Back to overview: nothing should
   change. The agent verifies the saved override is still present.
4. **Explicit repair:** reopen the review and select Clear selection and verify
   once. An Action receipt must distinguish verified, failed or unverified, show
   the actual checked version when successful, and avoid claiming package health,
   shell setup or updates. Reopen saved results: the same receipt must remain.
   The agent verifies exactly one mutation and unchanged packages/shell files.
5. **Presentation/accessibility:** with the evidence/review open, check Light and
   Dark, a long-label language and the prepared expansion scenario. Traverse
   actions/disclosures with Tab and Shift-Tab, and use VoiceOver headings and
   navigation. Labels should read title before count, focus rectangles should
   match the element, and changing language should update the current view
   without losing review/receipt state.

Unknown outcomes and stale reviews require separate controlled agent checks:
never simulate these by hard-stopping the VM or tell the owner to click Apply
