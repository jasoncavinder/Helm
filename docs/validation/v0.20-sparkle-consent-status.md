# Authenticated Sparkle Consent History

Date: 2026-10-03. Base: `20b91a90` (merged #626). Scope: a bounded,
authenticated **read-only diagnostic**, not direct updating or adoption authority.
Tracks part of #607; #606/#608 operational and release gates remain open.

## Contract

`consentStatus` accepts the same strict path/bundle-ID/installed-build intent as
ordinary app preflight, only after bidirectional signed-peer readiness. It accepts
no database path, consent token, trusted observation, feed or permission override.
Fresh native helper, OS-account root and target observations surround inspection.
Known manager claims, unsafe targets and request/native identity mismatch are
rejected before storage access. Changed evidence cannot publish saved history.

| Wire code | State | Meaning |
| --- | --- | --- |
| 20 | `notRecorded` | Valid existing ledger has no record for this app path. |
| 21 | `recorded` | Latest nonrevoked record matches the current consent identity. |
| 22 | `revoked` | Latest path record is a revocation. |
| 23 | `identityChanged` | Saved consent does not match current consent identity. |
| 24 | `ledgerUnavailable` | Missing, incomplete, corrupt, unsafe, busy or incompatible storage. |
| 25 | `targetRejected` | Fresh target/request checks did not permit history inspection. |

These codes are disjoint from preflight codes. The client validates the response
against the pending method. Invalid requests and identity/transport loss fail the
session rather than reporting successful history. Both methods share eight total
requests, strict sequence/replay checking, one in-flight operation, the 8 KiB
request bound, 15-second request deadline and 120-second connection lifetime.
Cancellation/expiry suppress late results; they do not promise interruption of
an already running read-only OS/SQLite call.

`recorded` is history at a read snapshot, not `Authority::UserAdopted`, update
eligibility, continued permission or permission to skip review. No consent ID,
epoch, sequence, fingerprint or reusable authorization token crosses XPC.
Operational admission must still resolve fresh evidence and recheck the latest
grant in its claim/handoff/verification transaction. Unknown apps remain Open App.

## Existing-Only Storage

The native private-directory lease opens the fixed OS-account helper namespace
with creation disabled. It never creates missing parents, lock files or databases,
and does not accept HOME/`HELM_DB_PATH`/client overrides. Descriptor, file identity,
permissions, ACL and sidecar checks remain around the read; cooperative lock
contention fails closed. No path escapes after lease release.

Core opens SQLite READ_ONLY/NOFOLLOW, not the normal migrating constructor. It
checks exact current schema, immutable migration names/checksums, quick integrity,
adoption epoch and session tables inside a single read transaction. No migrations,
repairs, consent writes, schema changes or normal WAL-configuration writes occur.
The historical migration manifest is unchanged.

Committed WAL revocations remain visible; uncommitted changes do not. Do not use
`immutable` or ignore WAL to make a read look nonmutating. SQLite may use/create
normal WAL/SHM bookkeeping, so this is not a byte-for-byte sidecar immutability
claim. See SQLite's [open flags](https://www.sqlite.org/c3ref/open.html) and
[read-only WAL behavior](https://www.sqlite.org/wal.html#read_only_databases).
This remains ordinary local storage, not protection against root/same-account
tampering, historical backup restoration or unrelated noncooperating processes.
