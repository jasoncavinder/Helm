# Authenticated External App Preflight

Continuation of #607 from merged #623 (`6b5bb757`). This is the first
target-specific read-only request, not complete ledger/session integration,
adoption activation or an external installer. #606/#607/#608 remain open.

## Contract

- The first hello remains data-free. The client sends app intent only after
  Foundation's fixed notarized helper requirement, challenge/version/account
  validation and authenticated reply. The existing exact caller requirement
  gates every delivered request; identity policy and shipping entitlements do
  not change. There is no operational fallback after transport loss.
- A fresh random per-connection token and strictly sequential request number
  bind the request. Reject pre-hello, cross-session, duplicate, overlapping and
  over-budget messages. There are at most eight requests per connection, an
  8 KiB request limit, a 15-second inspection deadline and the existing
  120-second connection/process lifetime. A result rechecks monotonic deadlines
  independently of timer callback delivery.
- Rust owns strict decoding: version, UUID, canonical permitted app path,
  expected bundle ID and installed build only. Unknown/duplicate fields,
  arbitrary roots, database paths, feeds, native observations and authority
  claims are rejected before target inspection. Roots come from the helper's
  OS account, not HOME or a request. Matching fresh native path/ID/build is
  required before returning the existing shared target assessment.
- The helper re-observes its native self-identity before and after collecting
  fresh native target/exclusion evidence. Failed inspection is an explicit
  failure, never a successful empty scan. Helper/root drift closes the session.
  The response is a bounded assessment code, not serialized private filesystem
  evidence, a trust receipt or an adoption/update authorization.
- Inspection runs on a separate serial worker. Cancellation/loss/expiry settles
  the pending reply once and drops late results without blocking connection
  control. A read already in progress may finish; this is not force-cancellation
  of an OS signing call. The helper process still has its fixed lifetime bound.

No database is opened or created, and no saved consent is read/written. Incomplete
native manager coverage means even successful preflight remains unresolved.
No `BoundaryObservation` or install permission is fabricated from a handshake.
The helper is still unembedded; Open App and all GUI/CLI capabilities are
unchanged. The QA-only probe can request preflight after readiness but must never
be installed/launched as Helm on the production host.
