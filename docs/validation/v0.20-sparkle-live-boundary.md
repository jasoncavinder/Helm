## Evidence Construction And Lifetime

`ExternalUpdaterPrivateServiceHost` owns `NSXPCListener.service()`. Its delegate
requires the identical listener, a single accepted connection and freshly
matching helper evidence before constructing `PrivateServiceAcceptance`. That
type has a file-private initializer and is not Codable or a public API.

The server applies the unchanged production peer requirement before activating
the connection. Hello and each exported operation capture whether
`NSXPCConnection.current()` is the exact accepted connection **before** queue
dispatch. A listener acceptance or requirement configuration alone is not
authenticated delivery. Wrong-connection/direct invocations cannot reach native
target work through this route.

The context moves from accepted to established only after valid bounded hello.
Worker observations require matching non-root real/effective/peer accounts, an
unclosed session and monotonic age below 120 seconds. Native helper observation
must match the accepted identity before and after work. Connection loss and
local cancellation close the boundary without waiting for the worker; expired
or changed evidence cannot publish a successful result. Existing per-request
sequence, 15-second deadlines, eight-request limits and synchronous commit
admission are unchanged. OS loss is acted on when its handler is delivered;
these checks are not a remote-process liveness oracle or an atomic path lock.

The six local ABI facts have these sources:

| Fact | Native source |
| --- | --- |
| Authenticated live caller | Actual delivered message on the requirement-configured connection, valid hello and bounded live context |
| Developer ID signatures / notarization | Exact native caller requirement and freshly checked dynamic/on-disk helper identity |
| Helm sandbox / direct-consumer channel | Fixed delivered caller requirement, not request fields |
| External helper unsandboxed | Owned private-service listener acceptance combined with fresh sealed service configuration/placement and the helper's no-entitlements contract |

The private launch model follows Apple's
[XPC service separation](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingXPCServices.html),
not child-process inheritance. Foundation's public SDK documents current-connection
identity during an exported-method invocation and rejects messages that fail
the configured [code requirement](https://developer.apple.com/documentation/foundation/nsxpcconnection/setcodesigningrequirement(_:)).
No private sandbox API or PID-based signing lookup is used. This does not imply
universal filesystem access or bypass App Management/TCC consent.

For now, these checks bracket existing private-route preflight, consent-history
and revocation work; the constructed value is not passed to the adoption bridge.
Mach/anonymous transport and standalone self-preflight cannot construct a
production private-service context. Debug-only fixtures test mapping without
claiming production authentication.

## Verification

Host compilation/static checks and explicitly authorized QA signing/notarization
were separate from runtime testing. All runtime checks ran in the disposable
macOS 27.0 (`26A5378j`) arm64 VM, not the owner's production Helm installation.

- Debug/test and Release Swift compilation passed with a freshly built optimized Rust bridge archive.
- All **261 native Swift tests** passed, including 11 new boundary tests.
- All **21 packaging** and **5 bridge-build** contracts passed.
- Strict SwiftLint for all eight changed Swift files, docs-sync and diff whitespace checks passed.
- An isolated negative-control build removed only the new per-request delivery guard. The targeted regression failed with the expected helper-access, target-access and accepted-result assertions; the real build passes.
- Apple accepted QA submission `5bfe0ad4-b1b6-45bc-893c-71d98cb34ca6`. All five wrappers were stapled, strictly verified and Gatekeeper-approved.
- All **nine signed private-peer cases** passed using the new helper: valid hello, Rectangle preflight, changed build, absent target, wrong caller ID, wrong channel, unsandboxed caller, impostor response and fresh valid connection.

The valid target/fresh connection returned `unresolved`, changed build returned
`targetChanged`, and absent target returned `observationFailed`, all with
`canUpdate=false`. The impostor started and received the data-free hello, but no
target intent. Rectangle's Info.plist and executable hashes remained unchanged;
no isolated development database was created. No adoption, update or package
lifecycle was attempted, and accepted owner-QA profiles remain untouched.

Failed attempts are retained, not counted as passes: the first sandboxed SwiftPM
compile hit nested-sandbox permission failure and was rebuilt with approval;
one source-archive attempt named nonexistent directories and was corrected before
transfer; the initial new post-hello test used a nonexistent Mach service, raced
with invalidation, and was corrected to use a real anonymous XPC connection.
The final suite and negative control validate that corrected test.
