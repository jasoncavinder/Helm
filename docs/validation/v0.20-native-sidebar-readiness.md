# v0.20 Native Sidebar Readiness

This record validates the Issue `#497` conversion of Dashboard and Settings
navigation from fixed custom sidebar containers to native macOS split-view
sidebars. It does not reopen Wayfinder information architecture or introduce the
future multi-theme system.

## Automated Evidence

- [x] Dashboard and Settings use semantic `NavigationSplitView` sidebar columns.
- [x] Both columns retain native list/sidebar navigation behavior and use one
  shared restrained Original Wayfinder surface sampled from the approved design:
  pale blue at the upper-left through near-white at the lower-right.
- [x] `NavigationSplitView` remains the outer navigation shell on every supported
  release, while the trailing inspector stays inside the detail column as a
  SwiftUI `HSplitView` and cannot resize or reposition the outer window.
- [x] Sidebar width constraints remain bounded while allowing native resizing.
- [x] Dashboard and Settings use title-free full-size chrome, and their shared
  sidebar surface extends through the title-bar safe area beneath the traffic
  lights and native toggle.
- [x] Dashboard application-menu visibility state maps deterministically to the
  native split-view visibility contract.
- [x] Focused arm64 tests pass on the macOS 13 deployment target:
  `ControlCenterSplitViewBridgeTests` (2 tests, 0 failures) plus the Settings
  opening/panel policy suite.
- [x] Full repository quality gate passes from the final branch revision
  (`HELM_XCODE_ARCH=arm64`, 189 macOS tests, 0 failures).
- [ ] Protected-branch CI passes after the implementation PR is opened.
