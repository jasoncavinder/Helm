# v0.20 Native Sidebar Readiness

This record validates the Issue `#497` conversion of Dashboard and Settings
navigation from fixed custom sidebar containers to native macOS split-view
sidebars. It does not reopen Wayfinder information architecture or introduce the
future multi-theme system.

## Automated Evidence

- [x] Dashboard and Settings use semantic `NavigationSplitView` sidebar columns.
- [x] Both columns retain native list/sidebar navigation behavior and use one
  shared restrained Original Wayfinder surface sampled from the approved design:
  pale blue at the upper-left through near-white at the lower-right.
- [x] `NavigationSplitView` remains the outer navigation shell on every supported
  release, while the trailing inspector stays inside the detail column as a
  SwiftUI `HSplitView` and cannot resize or reposition the outer window.
- [x] Sidebar width constraints remain bounded while allowing native resizing.
- [x] Dashboard and Settings use title-free full-size chrome, and their shared
  sidebar surface extends through the title-bar safe area beneath the traffic
  lights and native toggle.
- [x] Dashboard application-menu visibility state maps deterministically to the
  native split-view visibility contract.
- [x] AppKit enforces Dashboard and Settings minimum sizes, keeps restored
  Dashboard frames fully onscreen whenever the visible display can satisfy the
  Dashboard minimum, and presents the development-gated first run in a fixed
  `960x600` frame before restoring normal Dashboard geometry.
- [x] Focused arm64 tests pass on the macOS 13 deployment target:
  `ControlCenterSplitViewBridgeTests` (2 tests, 0 failures) plus the Settings
  opening/panel policy suite (15 tests, 0 failures), including oversized restored
  frames and displays smaller than the Dashboard minimum.
- [x] Full repository quality gate passes from the final branch revision
  (`HELM_XCODE_ARCH=arm64`, 197 macOS tests, 0 failures).
- [ ] Protected-branch CI passes after the implementation PR is opened.

## Current macOS Visual QA

Dashboard:

- [ ] Exactly one native sidebar toggle appears in the toolbar.
- [ ] The toolbar toggle and application-menu Show/Hide Sidebar command stay in
  sync through repeated collapse and restore operations.
- [ ] The sidebar can be resized within its intended bounds without clipping
  Helm branding, workspace labels, Plan badges, Environment, Settings, or status.
- [ ] Workspace selection, Environment routing, Settings routing, inspector
  presentation, and sidebar footer actions remain unchanged.
- [ ] Showing and hiding the inspector leaves the Dashboard window frame and
  leading sidebar position unchanged, with neither edge clipped.
- [ ] Dashboard cannot resize below `1024x640`, and restored frames keep both the
  sidebar and inspector edges fully onscreen whenever the display can satisfy
  that minimum.
- [ ] Search remains at the trailing edge of the title-bar area, standard actions
  remain in the native action area, and the compact circular Upgrade All control
  appears without a blank principal title or stray separator.
- [ ] Plan authority headings are visible, and its native outline presents a
  vertical Wayfinder card list while retaining manager subtitles, full-row
  selection, leading inclusion controls, trailing status, action buttons, and
  keyboard behavior. Filtering and clearing the Plan preserves each authority
  section's prior expanded or collapsed state.
- [ ] No redundant `Helm Dashboard` title is visible.
- [ ] Active and inactive window chrome, Wayfinder tint, and detail surfaces look
  native and remain legible in light and dark mode.

Settings:

- [ ] Exactly one native sidebar toggle appears and remains leading-aligned.
- [ ] No redundant `Helm Settings` title, title button, or stray separator is
  visible.
- [ ] Sidebar collapse, restore, resizing, and pane selection remain reliable.
- [ ] Settings cannot resize below `600x420` or above `760x600`.
- [ ] The restrained Wayfinder sidebar surface and solid detail surface remain
  visually distinct without competing large-area gradients.

First run:

- [ ] The development-gated Environment Brief uses the same title-free window
  chrome without introducing a blank title-bar band.
- [ ] Traffic lights remain legible, the composition remains unified, and only
  the software-source list scrolls when source coverage is long.
- [ ] The first-run frame remains fixed at `960x600`; completing first run restores
  the resizable Dashboard and its `1024x640` minimum.

Accessibility and appearance:

- [ ] Full Keyboard Access reaches every sidebar route in both directions.
- [ ] VoiceOver announces sidebar navigation, selection, badges, and footer
  actions without duplicate controls.
- [ ] Increased Contrast remains legible.
- [ ] Reduce Transparency remains legible on the opaque Wayfinder sidebar
  surface.
