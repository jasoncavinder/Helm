# v0.18.1 Scope Closure Audit

This document provides evidence-backed traceability for the `v0.18.1` exit criteria, confirming the released runtime scope is complete and factual.

## 1. SQLite Doctor Finding Lifecycle
- **Evidence**: `core/rust/crates/helm-core/src/sqlite/migrations.rs` (`MIGRATION_0017`) and `core/rust/crates/helm-core/src/sqlite/store.rs`.
- **Details**: `doctor_scans`, `doctor_scan_scopes`, `doctor_findings`, and `doctor_finding_aliases` persist scan coverage and finding lifecycle. Applied repair outcomes are recorded separately in `repair_history`.

## 2. Deterministic v2 Fingerprints
- **Evidence**: `core/rust/crates/helm-core/src/doctor.rs`
- **Details**: Fingerprints are generated deterministically based on manager, issue type, and stable context, keeping sensitive local paths outside of shared inputs.

## 3. SQLite-Backed Repair Knowledge
- **Evidence**: `core/rust/crates/helm-core/src/persistence/repair_knowledge.rs`, `core/rust/crates/helm-core/src/sqlite/store.rs`, and migration 17's `repair_knowledge_*` tables.
- **Details**: Persisted knowledge retains locally assigned source/trust metadata, revisions, selectors, option/action bindings, policy, checksums, import audit, and local overrides.

## 4. Bundled Knowledge Bootstrap
- **Evidence**: `core/rust/crates/helm-core/resources/bundled_knowledge.json`, `core/rust/crates/helm-core/src/persistence/repair_knowledge.rs`, and `SqliteStore::ensure_bundled_repair_knowledge` in `core/rust/crates/helm-core/src/sqlite/store.rs`.
- **Details**: The versioned bundled envelope seeds local SQLite through the same strict parser and import boundary. No network lookup is required.

## 5. Import/Export Hardening
- **Evidence**: `core/rust/crates/helm-core/src/persistence/repair_knowledge.rs` and `core/rust/crates/helm-core/src/sqlite/store.rs`.
- **Details**: Imports deny unknown fields, validate schema/identifiers/order/policy and compiled bindings, canonicalize with RFC 8785 JCS, verify the SHA-256 envelope checksum, reject protected-source claims/trust escalation, and transactionally reject downgrade/equivocation. Optional signature metadata is structurally validated but does not receive cryptographic trust: `VerifiedSigned` imports fail closed until a local verifier is configured.

## 6. Typed-Action Allowlisting
- **Evidence**: `core/rust/crates/helm-core/src/repair.rs` (`REPAIR_ACTION_DEFINITIONS`, `validate_knowledge_binding`) and `core/rust/crates/helm-core/src/persistence/repair_knowledge.rs`.
- **Details**: Knowledge can select only the four compiled repair actions and their protected option bindings. Unknown/rebound actions fail closed; knowledge cannot supply commands, arguments, scripts, plugins, or executables.

## 7. Repair Plan/Apply/Revalidation/Verification
- **Evidence**: `core/rust/crates/helm-core/src/repair.rs`, `core/rust/crates/helm-core/src/persistence/doctor_persistence.rs`, and the CLI/FFI repair apply paths.
- **Details**: The repair lifecycle follows a rigid before/after contract. A plan is proposed, revalidated against current state, executed via typed actions, and verified post-execution.

## 8. Scan Behavior (Full/Scoped/Partial/Failed/Cancelled)
- **Evidence**: `core/rust/crates/helm-core/src/doctor.rs`, `core/rust/crates/helm-core/src/persistence/doctor_persistence.rs`, and doctor scan completion logic in `core/rust/crates/helm-core/src/sqlite/store.rs`.
- **Details**: Doctor scans support targeted manager scopes and gracefully handle partial failures or explicit user cancellation without abandoning the session state.

## 9. Local Security-Advisory Domain and Cache Groundwork
- **Evidence**: `core/rust/crates/helm-core/src/security_advisory.rs`
- **Details**: The internal data structures and local cache domain for security advisories are present. Network fetchers and public CLI/GUI surfacing are deferred to `0.19.x+`.

## 10. CLI/Coordinator Contract Groundwork
- **Evidence**: `start_scoped_upgrade_workflow`, `scoped_upgrade_workflow_steps`, and cancellation/active-state FFI functions in `core/rust/crates/helm-ffi/src/lib.rs`.
- **Details**: Bulk/scoped authority-phase planning, task submission, terminal waits, and later-phase cancellation gating are backend-owned; presentation sends intent and consumes task/workflow state.

## 11. Migration-17 Reconciliation
- **Evidence**: `reconcile_replaced_migrations` and migration-identity validation in `core/rust/crates/helm-core/src/sqlite/store.rs`, plus canonical definitions in `core/rust/crates/helm-core/src/sqlite/migrations.rs`.
- **Details**: Addressed the collision between development migration 17 and released doctor migrations, preserving package identifiers and user data.

## 12. Historical-DDL Replay Prevention
- **Evidence**: `SqliteStore::apply_migration`, `validate_applied_migration_identities`, and migration checksum backfill in `core/rust/crates/helm-core/src/sqlite/store.rs`.
- **Details**: Current databases validate recorded migration identities and return without replaying historical DDL; new migrations run only above the recorded current version.

## 13. Upgrade/Recovery Coverage
- **Evidence**: Verified clean install, upgrade from `v0.17.12`, and database recovery for affected `v0.18.0` users as part of the `v0.18.1` release gates (referenced in `docs/PROJECT_BRIEF.md` and `CHANGELOG.md`).

## Conclusion
No critical gaps exist in the published `v0.18.1` scope. The runtime groundwork is successfully delivered, and all further UI and first-run orchestration will build upon this foundation in `0.19.x`.
