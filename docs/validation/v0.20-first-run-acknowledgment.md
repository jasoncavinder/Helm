## Contract

- `FirstRunExperience::WayfinderV020` has wire ID `wayfinder-v0.20`. It identifies
  the experience, not a particular RC, stable, or patch application version.
- `FirstRunStore` reads and acknowledges that experience in the shared database.
  It uses `app_settings` key
  `first_run.experience.wayfinder-v0.20.acknowledged`; no schema migration or
  historical migration change is needed. Future experiences get distinct keys.
- Missing key means unacknowledged. Only exact value `1` means acknowledged.
  Unknown values and storage failures return an error, not a fabricated pending
  or completed state. An acknowledgment write does not overwrite malformed data.
- The write is transactionally idempotent, including across separate database
  connections. Explicit local-data reset clears it. Normal reopening and later
  builds using the same experience ID do not clear it. The existing SQLite
  durability policy still applies; this is not a new power-loss guarantee.
- Legacy CLI onboarding completion, accepted terms, manager enablement, settings,
  pins, inventory, and task history remain independent. No previous application
  version metadata is required. No commands, network requests, or manager actions
  are dispatched by either endpoint.

## Service Boundary

`helm_get_first_run_experience_state()` returns caller-freed JSON:

```json
{"schema_version":1,"experience_id":"wayfinder-v0.20","acknowledged":false}
```

Null means unavailable/error. `helm_acknowledge_first_run_experience(id)` accepts
only a supported exact ID and returns false on failure. Both exports use the
existing service error-key convention; the C header documents string ownership.
The XPC methods `getFirstRunExperienceState` and
`acknowledgeFirstRunExperience` preserve the nullable-state and success/failure
boundary. Swift identifiers containing embedded NUL are rejected before C-string
conversion so a longer invalid ID cannot acknowledge a truncated valid prefix.

Future presentation consumers must validate schema/experience, keep loading/error
distinct from pending, and acknowledge only explicit completion or Use Helm Now
in the real experience. A failed write must not be represented as saved success.
Preview fixtures, opening/closing a window, and language changes must not write
this marker. Acknowledgment grants no terms, network, mutation, privilege,
automatic-update, or setup-action consent, and is not a verification receipt.
