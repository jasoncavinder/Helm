Date: 2026-09-27. Follow-up to

## Contract

- FFI previews carry `cargo_candidate_version` in the existing round-tripped
  plan metadata. Full reviewed-step equality rejects changed candidates before
  submission. Missing candidate metadata cannot fall back to a latest lookup.
- Accepted workflow steps retain that version after review. Legacy bulk
  submission captures each cached candidate too. Direct FFI package upgrades
  honor an explicit version instead of discarding it.
- Individual GUI Cargo upgrades submit the displayed candidate. Failed-step
  retries retain the reviewed Cargo candidate and existing uv scope/version;
  missing reviewed metadata fails closed instead of requesting an unbound retry.
  Retry metadata belongs to the actual submitted task, not the current preview:
  a refreshed candidate or uv store cannot silently retarget a failed task.
  Removal selectors and unrelated manager requests are unchanged.
- CLI foreground and coordinator workflows capture the cached Cargo candidate
  when forming their execution steps and share one upgrade-request builder.
  JSON preview adds `candidateVersion` only to Cargo rows; text shows the target.
  Existing uv scope/version binding and Homebrew cleanup encoding are preserved.
- A Cargo upgrade candidate older than native installed inventory fails before
  mutation, using SemVer precedence (including prereleases, excluding build
  metadata). This also protects against a package being upgraded outside Helm
  while a cached plan is waiting. Already-current targets remain verified no-ops.

CLI preview and run are separate commands, not saved review/approval tokens.
Detached workflows form their plan when the coordinator starts that workflow.
Unversioned direct `packages upgrade` still resolves once at task start. This
change does not add a `--version` option to that command.

## Remaining Limits

Retry bindings use the existing live task-label metadata, not a new persisted
approval record. If that metadata is unavailable (for example, for older tasks,
after service restart, or from a coordinator that does not supply it), Cargo/uv
Retry fails closed; the user must review and submit a new plan. No version or
scope is reconstructed from a newly refreshed preview or a human-readable label.

This binds a version, not the selected executable, installation root, registry
source, feature/bin/profile/target choices or artifact hashes. Those contracts,
published-lockfile behavior and signed GUI parity remain open. General
dependency policy and cargo-binstall are unchanged. The native locked
slint-viewer experiment is still not a Helm dependency-policy repair.

No release, certification or participant gate is waived.
