# Cargo VM CLI Lifecycle Regression

The opt-in `scripts/tests/cargo_vm_cli_lifecycle.py` makes the real Cargo
certification sequence repeatable. It is a test harness, not a new manager API,
installer, release gate waiver, or general certification of registry packages.
Run only in the disposable VM or an explicitly disposable macOS runner, with
Python 3.11+, Command Line Tools and an already installed Rustup toolchain.

## Isolation and Coverage

The script requires explicit disposable-environment confirmation and absolute
Helm/Rustup/toolchain/artifact inputs. It creates a new private HOME, Cargo home,
install root, build target, temporary directory and Helm database. It does not
inherit arbitrary process environment, use a project Cargo configuration,
install/update the selected toolchain, uninstall managers, or remove evidence.
The selected preinstalled Rustup toolchain is shared read-only for these commands;
the test does not claim operating-system enforcement of that read-only intent.

Registry access is real. The fixture installs `sd` 0.7.6 and `hyperfine` 1.18.0
using native Cargo with `--locked`, then runs Helm detection, refresh, inventory,
two-item Plan preview and execution. Assertions require both cached reviewed
scopes, exact candidate versions in persisted inventory, preserved native build
options and successful independent executable version probes. The first package's
receipt update must not invalidate the next package's reviewed scope.

Further checks cover empty Plan/no-op rerun, removal preview without mutation,
target removal with its sibling binary unchanged, final-tool removal, empty
refresh/inventory, fresh install into the empty receipt store, and preservation
of native `--no-default-features --profile dev` choices on a Helm reinstall.
The last fixture is removed through Helm. Task records must all be completed and
SQLite integrity must be `ok`. Logs and receipts remain for inspection.

Each subprocess uses structured arguments and a bounded timeout. The harness
retains ownership of its new process sessions across commands: a persistent CLI
coordinator can belong to an earlier command's session, and Cargo children have
their own process groups. Timeout/interruption and final lifecycle cleanup stop
all live members of those owned sessions using bounded TERM/KILL escalation,
rechecking membership before signaling. Completed session IDs are discarded;
unrelated sessions are not signaled. Process inventory uses portable `ps` PID and
state fields plus `getsid`, not the platform-dependent `ps sess` field. This is
containment for inherited sessions, not an OS sandbox against deliberately
escaping processes or a rollback of completed package changes.

Captured output is retained where available and a failed operation is never
retried automatically. Nine harness regressions cover environment and working
directory, failure diagnostics, direct-child timeout/reaping, separate process
groups, a prior coordinator-like worker and unrelated-session safety, KILL
escalation, completed-session pruning, interruption and refusal without opt-in.
CI runs only those regressions, not networked Cargo package installs.

Example inside the VM, with paths replaced by its known test artifacts:

```sh
python3 scripts/tests/cargo_vm_cli_lifecycle.py \
  --helm /absolute/path/to/test/helm \
  --rustup /absolute/path/to/preinstalled/rustup \
  --rustup-home /absolute/path/to/preinstalled/rustup-home \
  --toolchain stable-aarch64-apple-darwin \
  --artifacts /absolute/path/to/disposable/evidence \
  --confirm-disposable-environment
```

Do not use the host production CLI/database or a user Cargo install root. A
changing registry, unavailable published lockfile, compilation problem or network
failure is retained as a failure, not hidden by unlocked or version fallback.

### Independent review follow-up

PR #592 review reproduced the old cleanup defect in the disposable VM: after
the timeout helper returned, a fixture child in its own process group was still
alive. The regression terminated that exact recorded fixture PID in `finally`;
no native Cargo installation was used for this reproduction. Lifecycle-wide
session ownership now also covers workers retained from earlier successful
commands. All nine focused harness regressions passed three consecutive times
in the disposable macOS VM (27 executions) with Python 3.14.7. The reviewed
script SHA-256 is
`2df25e9937fd29fdd632f487755660b2d72cea8bec97deb302d40f636805c75f`;
the host-retained VM log `/private/tmp/helm-pr592-owned-session-final-tests.log`
has SHA-256 `cac8296dcdfc0d2514cf5bd02e540a0e96a68766a5021a9f58c5ee4623262909`.
The native 28-command lifecycle evidence above remains historical, not a claim
that package installs were repeated for the cleanup-only change.

This does not replace signed GUI acceptance, Ventura/Intel runtime coverage,
unsupported Git/private-registry/source contracts, the separate cancellation and
failure evidence, or all-adapter certification. It does not alter Cargo's source,
published-lock, verification or review-scope policies.
