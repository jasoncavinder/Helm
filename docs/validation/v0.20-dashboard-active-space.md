## Correction

Dashboard creation retained a normal `NSWindow` after close, but presentation had
no explicit active-Space collection policy. Reopening could reactivate its old
Space. The presentation boundary now applies AppKit's `moveToActiveSpace` before
both `makeKeyAndOrderFront` and app activation. This is the documented native
preference to move a window to the active Space rather than switch Spaces:
[Apple collection behavior](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/movetoactivespace).

The policy removes the mutually exclusive join-all-Spaces flag if encountered
and preserves unrelated flags. It does not add a floating level, transient mode,
all-application override, child relationship, window recreation or delayed
Space-switch workaround. An already fullscreen Dashboard keeps its own Space
policy. Frame restoration, minimum sizing, toolbars, popover routes and Settings
presentation are unchanged. Explicit Dashboard presentation uses the active
Space preference; this is not automatic following while switching desktops.
