## 1. pnpm Compatibility Message

In Environment, select the staged pnpm installation and refresh it. In Library,
confirm that prettier 3.5.3 and semver 7.6.3 are both visible. Select only prettier
for an update attempt; the attempt must fail before mutation, not report success.
In Activity, select that failed task and open **View Diagnostics**.

Expected: the explanatory text says Helm cannot safely change this pnpm version's
global packages, that reads remain available, and that the complete group needs
review in pnpm. It must not suggest downgrading/reinstalling the scope. Switch
Helm to a second language and reopen diagnostics; guidance must be translated,
legible and reachable with VoiceOver. Raw diagnostic output may remain English.
The agent verifies both original installed versions still exist and refresh still
works. Repeating every CLI mutation test in the GUI is unnecessary.

Known limit: updates are still discoverable/included in preview and actions are
rejected at execution. Proactive version-specific action presentation and full
group-aware support remain in [#559](https://github.com/jasoncavinder/Helm/issues/559).
This test does not certify pnpm 11+ mutations.

## 2. Developer-Tools Prerequisite

The agent stages an isolated service environment with developer tools unavailable
and proves that environment applies to the service, not just its launcher. On the
existing CLT-equipped VM, an invalid scoped `DEVELOPER_DIR` is a simulation only;
do not uninstall CLT to produce this case.

Attempt the supplied harmless Cargo source-install fixture, then open the failed
task's **View Diagnostics**. Expected: a clear translated explanation that this
operation needs Apple developer tools, including `xcode-select --install`, with
no compiler process/package installation and no automatically launched Apple
installer. Cached inventory remains usable. Check English and one other locale.
The agent restores the service environment before subsequent tests.

A genuinely CLT-free machine still needs a separate launch/read-only/binary-action
test. This simulation must not be recorded as that platform's certification.

## 3. Cask Authorization Boundary

The agent supplies the isolated controlled cask and identifies the expected
authorization request. Review its installation in Helm, start it, and cancel the
authorization request. Expected: no success indication or installed fixture;
failure/cancellation is visible and Helm remains responsive.

Repeat and approve only the described fixture. Expected: the task completes and
the actual installed version/marker matches the reviewed candidate. The agent
verifies Homebrew itself ran as the ordinary user, only its required child work
was elevated, and no unrelated installation changed. Remove the fixture through
Helm after recording evidence. This validates the current delegated authorization
path, not activation of the future privileged-helper implementation.

## 4. Sparkle Vendor Handoff

Select the staged app's Sparkle item in Plan and use **Open App to Update**.
Expected: the correct vendor app opens, and Helm does not label the handoff as a
completed automatic installation or start the vendor's updater executable itself.
If the vendor offers an update, complete it through that app, then refresh Helm:
the observed installed version and candidate must reconcile. If the vendor offers
no candidate or requires an account, record blocked, not passed.
