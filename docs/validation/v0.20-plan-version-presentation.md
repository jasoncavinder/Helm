# Plan Version Presentation

## Scope

Cargo signed-GUI parity exposed missing version transitions in Plan cards:
the owner could see only the internal `cargo_candidate_version` argument in the
Inspector. Plan cards and the execution-review sheet now show installed-to-target
versions, and the Plan Inspector names Installed Version and Target Version.
The seven supported locales include the new target label; VoiceOver receives
named versions rather than relying on the visual arrow.

The FFI preview captures `plan_installed_version` and `plan_candidate_version`
in the existing reason-argument map from the same outdated snapshot used to
build its steps. The reviewed JSON retains this evidence and the existing
review-equality guard rejects a changed snapshot. This does not pin versions for
managers whose native upgrade operation selects its own current candidate.
Cargo/uv retain their existing version/scope-bound execution. No mutation policy,
package selection, manager ordering, or database schema changes are introduced.

Matching is manager/package scoped; missing, ambiguous, and aggregate targets
do not acquire an invented version. A single known side is retained with a
localized Unknown for the missing side. External Sparkle and Helm self-update
steps capture their own version evidence while retaining interactive authority.
Research fixtures use the same presentation contract.
