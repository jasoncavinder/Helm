Tracks #500/#526 and supplements the [family results](v0.20-adapter-vm-family-results.md).
The family record supplies exact manager versions, fixture packages, artifact
hashes, failure history and evidence IDs. This table does not expand supported
capabilities, approve release, or certify every version or installation method.

All live evidence is from the disposable arm64 macOS 27 VM with isolated Helm
databases and package scopes. The [original absent-state baseline](v0.20-adapter-vm-certification.md)
covers every registry ID, including policy rejection of system Python/Ruby.

## Declared Package Capabilities

- **P**: passing real CLI scenario in the bounded family record.
- **E**: passing empty/no-update result; no positive update candidate exercised.
- **B**: blocked by the stated account, authorization or environment boundary.
- **U**: applicable operation not yet exercised in this VM.
- **F**: reproduced failure; explanation/issue recorded, not certification.
- **-**: not declared by this adapter. A generic CLI refresh returning success
  for a detection-only manager does not add a Refresh capability.

`Install`, `Upgrade` and `Remove` below concern the adapter's package surface.
Installing or removing the manager executable through a provenance-owned
Homebrew route is a separate operation; those routes are not implied by `-`.
Search means the implemented contract, which may be local/installed-scope rather
than a remote registry catalog. Query caching is not proof of network activity.

## Policy and Recovery Evidence

- Native Homebrew formula pinning and Helm pin exclusion pass in the bounded
  formula/cask and language-tool lifecycle scenarios. uv additionally rejects a
  pinned targeted upgrade. These are not claims about every manager's pin API.
- Selected Python venv identity, Homebrew tap-qualified package identity,
  retained old versions and exact-version removal have live and deterministic
  regressions. Unknown executable ownership remains read-only for manager
  lifecycle operations; package operations retain their own capability policy.
- The real combined mise/npm/pip Plan honors pin exclusion, explicit consent,
  authoritative-first order and persisted post-update versions. This does not
  replace the planned v0.22 multi-manager stress/recovery campaign.
- uv 0.12.9 and 0.12.18 pass repeated authenticated-loopback cancellation,
  failed-auth cache retention, unsupported-source rejection, last-tool removal
  and reinstall. The duplicate CLI request publication defect has a real
  coordinator-process regression and repeated live reruns.
- Cask delegated authorization cancellation leaves the fixture uninstalled.
  Root-run MacPorts/Rosetta scenarios are not signed GUI authorization evidence.
- Core/process regressions cover malformed output and eligibility boundaries;
  unavailable-developer-tools simulation covers safe reads, blocked compilation
  and binary-only cargo-binstall. A real CLT-free OS is still required to close
  that environment gate. No blanket CLT requirement was added to Helm startup.

## Remaining Disposition

- **Account-blocked:** mas owned-app inventory/install/upgrade/removal. The owner
  explicitly deferred sign-in. Setapp account operations are also deferred, but
  are not capabilities of the current detection-only adapter.
- **Guarded-system:** no OS upgrade was authorized; no CLT update candidate was
  available. Do not manufacture success by updating the VM's operating system.
- **Version-changing evidence:** rustup's current-stable upgrade and persisted
  pin/unpin pass, but stable remains 1.98.1. Positive container-manager
  update candidates were unavailable. Passing empty results remain labeled E.
- **Interactive boundaries:** signed GUI authorization, Sparkle vendor handoff,
  and prerequisite presentation need targeted GUI checks, not repetition of all
  passing package lifecycles. CLI/core sharing does not prove UI authorization.
- **Platform coverage:** this VM supplies neither Ventura/Tahoe nor Intel runtime
  evidence. Compilation with a macOS 13 deployment target is not a runtime test.
- **Outside scope, not hidden failures:** nested container/VM operation,
  nix-darwin activation, Setapp package management and direct third-party
  Sparkle installation are not declared by these adapters.

Retain #500/#526 and the campaign PRs until the remaining applicable cells have
evidence or an explicit limitation/deferral decision. Keep raw evidence locally
when the VM is removed; do not publish private command output as a substitute for
the reviewed, bounded record.
