Date: 2026-09-27. Scoped follow-up to

[#564](https://github.com/jasoncavinder/Helm/issues/564), not issue closure.

## Implemented Contract

The process-backed Cargo upgrade path reads native `.crates2.json` before
mutation. A supported crates.io receipt supplies the exact binary set, features,
all-features/no-default-features flags, profile and target. These become
structured Cargo arguments alongside the already-bound candidate version and
explicit absolute install root. Root precedence follows the explicit scope or
`CARGO_INSTALL_ROOT`, home configuration `install.root`, then Cargo home.

Missing, duplicate, incomplete, ambiguous or unknown metadata fails closed.
Git/path/private-registry sources, source replacement/default overrides,
relative or non-UTF-8 roots, missing/symlinked binaries and overlapping binary
ownership require manual handling. Receipt/config reads are bounded regular
files. No features, sources, installer or dependency policy are silently replaced.

The captured receipt map is checked again immediately before execution. After
Cargo succeeds, Helm requires the exact candidate/source/options, existing
binary files and unchanged unrelated receipts. Native inventory verification
and durable task/result reconciliation from the earlier slices remain in force.
Preflight and postcondition failures expose the structured
`cargo_receipt_unsupported` marker with localized guidance in all seven locales.

## Remaining Limits

This is an execution-time upgrade guard, not a persisted review approval token.
The selected executable, root and receipt/source are not yet frozen at GUI
review time. Independent native Cargo processes can still race Helm; no
cross-process Cargo lock is held across the command, and no rollback is claimed.
Unrelated receipt changes are detected but cannot be undone automatically.

Install/reinstall/uninstall contracts and dependency lockfile selection are not
changed here. Cargo-binstall is unchanged. The locked slint-viewer reproduction
remains native evidence, not a Helm dependency-resolution fix. Keep #564,
signed GUI parity, all-platform certification and release gates open.
