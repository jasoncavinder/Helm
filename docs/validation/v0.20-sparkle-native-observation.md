# v0.20 External Sparkle Native Observation

Status: read-only development foundation, not an enabled update capability.
Depends on the [boundary contract](../architecture/EXTERNAL_SPARKLE_BOUNDARY.md)
and [durable session work](v0.20-sparkle-durable-session.md). No release or issue
gate is closed by this slice.

## Implemented Boundary

`service/external-updater` is a standalone macOS 13 Swift package. It is not
embedded in Helm, and has no installer, network fetch, privileged operation,
service endpoint, or signing configuration. Its optional development probe only
prints locally observed evidence; it is not the shipped Helm CLI.

- Resolve only concrete, canonical app paths beneath `/Applications` or the
  current OS account's Applications folder, never a caller-controlled `HOME`.
- Reject aliases, nested apps, escaping symlinks, unexpected file kinds, unsafe
  ancestor ownership/permissions and trees exceeding 100,000 entries.
- Preserve device/inode, owner/group, mode, size and change timestamps; repeat
  observation after native validation and reject changes rather than combining
  facts from different app versions.
- Read application and Sparkle framework metadata through no-follow descriptors,
  bounded to 2 MiB. Only Sparkle 2 metadata, HTTPS feeds and a 32-byte Ed25519 key
  are recognized. Helm's own bundle identifiers remain excluded.
- Validate a Developer ID application using Security.framework's strict,
  all-architectures and nested-code checks. Obtain the bundle dictionary from
  Security's signing information, not CFBundle's cached presentation dictionary.
  No Command Line Tools process is invoked and no certificate-network flag is
  enabled.
- Report App Store receipt and mutation-permission facts without deciding manager
  ownership. Mutation-grant ACLs conservatively count as unsafe even if the grant
  might resolve to the current user alone. `/Applications` allows its normal
  root/admin group-write mode, not arbitrary ACL grants or another group.
- Evidence is Encodable-only and always has `requiresAuthorityResolution=true`.
  A future client must not be allowed to supply it as trusted input.

The ACL reader queries a successfully retrieved file security descriptor to
distinguish an absent ACL from an unreadable one. This follows the distinction
in Apple's [ACL implementation](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_file.c)
and [file-security properties](https://github.com/apple-oss-distributions/Libc/blob/main/gen/filesec.c).
Errors remain fail-closed. Path comparisons deliberately use canonical path
strings rather than URL equality, which can differ for directory-form URLs.

## Verification

Unsigned arm64 compilation is performed on the host without running the product
or tests. Runtime checks execute in the disposable macOS VM only:

- 17 XCTest cases cover bounded metadata, signature rejection, path aliases,
  nested apps, internal/escaping symlinks, mode/ACL grants, safe read-only ACLs,
  ancestor checks, file/permission mutation, special files, and entry limits.
- The native unsigned fixture is rejected by Security.framework, independently
  of the injected signer used for deterministic filesystem tests.
- Read-only observation of the existing signed Rectangle 2.0.1 (build 108)
  reports Sparkle 2, 266 inspected entries, no App Store receipt and no unsafe
  mutation permissions. Its manager authority remains unresolved. Rectangle was
  not launched, updated or otherwise changed by this probe.
- Strict SwiftLint passes. The macOS CI job runs this package's tests explicitly.

Local evidence is under `artifacts/observer-vm-tests.log` and
`artifacts/rectangle-observation.json`; retain/redact local paths before sharing.
VM scope: `sparkle-native-observation-20260928`. This is macOS 13 deployment-target
compilation plus current-VM runtime evidence, not an actual Ventura run.

## Still Required

Bind these native facts to coordinator-owned manager authority and the shared
core snapshot contract; authenticate clients; observe helper identity,
notarization and consent; integrate Sparkle callbacks with durable authorization;
prove installer quiescence before recovery; and complete signed live update,
cancellation, interruption and post-install verification checks. Re-observe at
the actual installation boundary: this snapshot does not lock the filesystem or
grant mutation authority. Helm's sandbox and current vendor-app handoff are
unchanged.
