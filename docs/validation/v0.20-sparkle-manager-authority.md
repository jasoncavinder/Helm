## Contract

- Native target evidence now includes competing-manager exclusions, exact
  Homebrew reference paths, inspected-entry count and an explicit disposition.
  Evidence remains output-only; there is no public constructor, decoder or
  caller-supplied authority/root/command input.
- Read the two locally fixed standard Caskrooms, not environment overrides,
  cached Helm inventory, enabled-manager preferences or downloaded cask data.
  Enumerate only token/version/artifact levels, bounded to 10,000 entries total
  across roots, including ignored entries. Do not enumerate app contents or
  `.metadata`, execute brew/Ruby, or open artifact link destinations.
- Match exact lexical app paths, including normalized relative references,
  rather than cask names, display names or bundle IDs. Retain all matching
  references in deterministic order. A stale or forged matching reference may
  conservatively exclude an app, but can never authorize updating it.
  Normalize components in memory with explicit URL directory hints; no inferred
  directory status, filesystem standardization, tilde or symlink resolution.
- Descriptor-based enumeration rejects symlinked roots/ancestors/token/version
  directories, unreadable roots, invalid names/link text, unsupported layouts
  and bounds exhaustion. Only `ENOENT` at a root represents absence. Snapshot
  directory/entry identity and link text before and after target signature
  validation; drift requires fresh observation. Caskroom group-write permissions
  are not grants of installation authority: these are negative signals only.
- Derive App Store receipt-container presence from the already rechecked bundle
  snapshot, not an unchecked `fileExists` after validation. Empty or internally
  aliased `_MASReceipt` containers also exclude, without asserting receipt
  validity. Component-bounded `/Applications/Setapp/` and the OS-account's
  `~/Applications/Setapp/` locations add a separate exclusion.
- Disposition is only `otherManager` or `unresolved`. The output always retains
  `requiresAuthorityResolution = true`; there is no native standalone case.
  Missing markers do not establish absence of other authority. Custom Homebrew
  prefixes, pkg/custom installs, relocated/static-linked Setapp builds and other
  sources remain unresolved work, not silently supported standalone apps.

## Independent Review Correction

Review of PR #621 at `f98cbef8ef23411e02db6308b40d42a71b5f1ee9` found that
Foundation URL construction/standardization inferred directory status from
untrusted link destinations, outside the descriptor-bounded scan. This could
introduce unrelated filesystem access or blocking; it did not grant authority.
The finding was [posted before remediation](https://github.com/jasoncavinder/Helm/pull/621#issuecomment-5964657846).

Correction `6f2e9209a7bb8c8fcc6831aff5ee56096292eae9` replaces that path with
pure component normalization and explicit directory hints throughout the scanner.
The tested `service/external-updater` subtree is
`375c5d9d1875d1208418ef06fb3e1f24277fd078`; subsequent review documentation does
not change it. Four additional tests cover lexical normalization (including
root clamping and literal percent/Unicode/tilde text), inert directory hints,
absolute dot-component matching and relative aliases remaining unresolved.

The designated macOS 27 arm64 VM passed **all 100 native XCTest tests**, all
**17 packaging tests**, and the Sparkle/appcast dry-run checklist. Before the
fix, the directory-inference test was run with the original normalization
extracted unchanged into the new helper: it failed with two expected assertions,
one each for absolute and relative link text to an existing directory. This is
an observable directory-inference negative control, not syscall tracing or an
automount stress test. The same regression passes with the correction.

Fresh read-only current-source manager probes repeated the three exclusions and
Rectangle's unresolved result above. The full Rectangle probe again validated
build 108/team `XSYZ3E4B7D` and retained `requiresAuthorityResolution = true`.
No manager command, app update or helper registration ran. Host work was limited
to compilation/static checks: arm64 Debug/build-tests, universal arm64/x86_64
Release, strict no-cache SwiftLint, docs sync and whitespace checks pass. These
are not signed-helper, native Intel, Ventura-runtime or operational-update passes.
