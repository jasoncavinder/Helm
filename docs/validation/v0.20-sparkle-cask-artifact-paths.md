## Implemented Grammar

The receipt observer now interprets a finite set of declarative paths instead of
marking every non-app artifact uninspected. It never executes Homebrew, Ruby,
uninstall directives, scripts or vendor updaters, or probes artifact destinations.

| Installed declaration | Supported interpretation |
|---|---|
| `app`, `suite` | One source string, optionally one `target` string; basename or nonempty override resolved using saved default/env/explicit appdir precedence. |
| `artifact` | Source plus an explicit nonempty absolute `target`; no appdir dependency. Relative/empty targets remain gaps; missing required target is malformed. |
| `uninstall`, `zap` | One directive dictionary; `delete`, `trash`, `rmdir` may contain a literal absolute string or a bounded flat string array. |

Any path equal to, inside, or containing the inspected app is a competing claim,
using case-folded Unicode-normalized component boundaries. A suite directory can
therefore claim a contained app even without its moved-app symlink. Root claims
conservatively cover every target; similarly named sibling paths do not overlap.
Removal declarations are denial evidence even if they are optional zap behavior,
not proof that a removal ran or a grant of removal permission to Helm.

Unknown artifact types and directive keys remain `uninspectedArtifacts`, even
when another declaration supplies a valid claim. No script, pkgutil selector,
launchctl/signal/quit action or metadata option is classified as harmless merely
because it appears beside a recognized path. Binary destination/configuration
semantics and other artifact classes remain unimplemented. Empty removal forms
also remain gaps.

Globs, brace expressions, variable/interpolation syntax, backslash escapes and
account-relative paths are not expanded. Unsupported expansion-dependent forms
retain a gap or reject malformed input. Removal paths with dot segments are not
normalized into claims: Homebrew skips them, and this observer retains uncertainty.
Moved destinations preserve the existing lexical normalization behavior. This
does not resolve filesystem aliases or historical/custom ownership.

All earlier receipt/config byte limits, no-follow reads and snapshot revalidation
remain. New path bounds are 512 paths per removal declaration and 4,096 per
receipt. Malformed recognized argument shapes, mixed-type arrays, invalid text
and over-limit values fail closed rather than returning an empty success.
