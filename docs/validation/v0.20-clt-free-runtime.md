# v0.20 Command Line Tools Absence Check

## Scope and Result

On 2026-09-28 UTC, the owner approved use of the existing Developer ID identity
and temporary removal/restoration of Command Line Tools in the disposable macOS
27.0 (`26A5378j`) arm64 VM. The actual `/Library/Developer/CommandLineTools`
payload was moved to a root-only holding directory. There was no Xcode.app, and
`xcode-select --print-path` failed. No `DEVELOPER_DIR` override was used.

Apple's SIP-protected package receipts were intentionally left unchanged. This
is real absence of usable developer tools, including the common stale-receipt
case, not a pristine never-installed OS or an Apple installer/reinstall test.
SIP and signing credentials were not changed. The exact payload, compiler hash,
receipt and selected developer path were restored afterward.

## Stale Receipt Correction

The original adapter reported `installed=true` and the receipt version with
`executable_path=null` while the tools were physically absent. Detection and
installed inventory now require both the CLT payload's regular `clang` file and
a valid receipt version. Adapter refresh and outdated queries produce no CLT
packages when the payload is absent; refresh avoids `softwareupdate` entirely.
Full Xcode selected elsewhere does not make the separate CLT package installed.

Four regressions failed against the original behavior in the VM, then passed
with the correction. All 51 `helm-core` unit/integration test executables passed
in the VM, including 813 unit tests; five existing tests remained ignored.
Workspace Clippy with warnings denied, formatting and diff checks passed.

The corrected CLI (`27b05ea19002cff2ea2dc739539820b44590a745efb90548f6e2ec60134ae849`)
also passed a real installed/absent/restored round trip. Both absence and
restoration were verified without deleting receipts or invoking Apple's stubs.
The corrected adapter source blobs are
`26ea77d53a46c55158437ca8907fbe6be45abefc` and
`4c46a897a01175fb5695c934dc2a26df59b92588`.

One initial harness assertion incorrectly expected CLI refresh to erase its
last-known package cache. The CLI intentionally returns after absent detection,
before requesting inventory. The retained failed assertion and corrected rerun
show `installed=false`, null path/version, and unchanged cached packages. This
fix does not change that cross-manager caching policy. Direct adapter empty-
snapshot behavior is covered separately by the regressions.

Raw records remain private under the VM's `helm-certification/signed-0175`,
`clt-absent-0175` and `clt-detection-regression` directories, with copied local
manifests and logs. This closes the bounded launch/read/prerequisite check, not
all source-build paths, CLT upgrades, Ventura/native-Intel acceptance, owner GUI
acceptance, account-dependent checks, or release/canary authorization.
